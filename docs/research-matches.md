# 研究対局（v1.5.8 初版）

仕様確定日：2026-11-12（Asia/Tokyo）。対象は #275 の旧8「研究対局」の初期提供範囲です。

## 分岐と操作

- 検証に通る終了済みリプレイを読み込み、停止した状態で赤軍の手番開始へ移動し、「ここから研究対局」を押します。開始位置0、または青軍のターン終了直後が対象です。赤軍の途中・青軍手番・勝敗確定後は分岐できません。
- 人間が赤軍を操作し、青軍は新しいCPUが判断します。難易度は元リプレイの値を初期値とし、研究中に変更できます。元リプレイには軍方針がないため、分岐前に均衡・攻勢・守勢を明示選択します。初期値は均衡、規則v12未満は均衡のみです。
- 元の初期状態と分岐までの命令を保持して状態を再現します。規則版、乱数、偵察、物資、搭載、作戦目標の進捗を引き継ぎます。元リプレイの未来の命令と最終状態は研究対局へ渡しません。全体視点で見ていても、研究開始時は通常の赤軍視界へ戻ります。
- 「1手戻す」は研究開始後の操作だけが対象です。保存再開時は通常と同じくundo履歴を復元しません。「分岐点からやり直す」と結果画面の再挑戦は、同じ分岐点・研究扱い・現在のCPU設定を保ちます。
- 非同期の分岐準備中に再生位置・対局・画面等が変わった場合は分岐を中止します。通常の対局への切替は既存の対局置換確認を使います。

## 保存形式

研究は通常セーブschema4にフラグを追加する方式を採用しません。通常セーブの読込は追加キーを拒否しないため、旧版が研究を通常対局として扱う危険があるためです。独立した厳格なコンテナを使います。

```json
{
  "format": "ministr-research",
  "schemaVersion": 1,
  "origin": { "replaySha256": "元リプレイの正規化JSONのSHA-256（小文字64桁）", "branchIndex": 3 },
  "match": {
    "mapId": "...",
    "difficulty": "normal",
    "initialState": {},
    "commands": [],
    "gameState": {},
    "savedAt": "ISO日時",
    "cpuPolicies": { "red": "balanced", "blue": "balanced" }
  }
}
```

上記はフィールドの説明です。状態・命令は既存の検証に通る実データが必要です。`cpuPolicies`だけが省略可能で、外側・origin・matchの未知キー、未知の形式・版を拒否します。matchに通常のschemaVersion・mode・campaignScenarioId・redDifficultyを持たせません。研究コンテナと内側match単体はいずれも通常セーブ読込に通りません。

読込時は命令列から状態を再現し、保存状態との一致と分岐位置を検証します。研究はUTF-8で1,000,000バイト以内、既存の対話プレイ上限（盤面・部隊・命令数等）内です。SHA-256は元リプレイを識別する情報であり、ローカル編集への認証ではありません。

保存先は `ministr.research.auto` と `ministr.research.manual` の2枠です。通常の自動・手動・名前付きセーブを使いません。未知版や破損データがある枠は上書きせず、元データ書出し後に利用者が削除できます。容量不足時は研究JSON書出しで退避します。全データバックアップにも含み、復元時に検証します。研究キーを含むバックアップは旧アプリでは復元できません。

研究JSONは既存のJSON取込から再開でき、終了結果も研究として保存・書出しできます。通常リプレイとしての書出しは提供せず、通常セーブ復旧の対象にも変換しません。

## 結果への反映

研究で勝利しても、単体作戦記録・日替わり成績・キャンペーン進行を更新しません。終了した研究を取り込む／再開する場合も同じです。研究から通常保存を読み込む・新しい通常対局を開始する際は、研究扱いを明示的に解除します。

研究の結果表示に含まれる損失等は、分岐前を含む全履歴の集計です。分岐後だけの成績や認証付きランキングを意味しません。

## 今回の範囲外

人間青軍、途中の任意命令位置からの分岐、研究履歴の複数枝ツリー、研究結果のリプレイ閲覧からの再分岐、分岐後だけの比較集計は将来の拡張候補です。初版は元リプレイからの分岐・研究継続・同じ分岐点の再試行を提供します。戦闘・AI・勝敗規則、通常セーブとリプレイschema4は変更しません。
