基準はv1.4.4 main `6041c97fe7505c21667cf1869b811389a6f4e987`、tree `ed4bfc8cee8f08d127013b64acee6e67b1f83f9b`。同一treeのローカルworktreeから変更前をビルドした。計画のみのcommit `20b5f8fe9a00ee26ff98057e12001e551adfade0` で[ドラフトPR #262](https://github.com/kumakumapon/MiniStr/pull/262)を作成してから製品コードを変更した。

## 変更

- `screenView`：画面テンプレートのうち盤面へつながる6つの構造要素を接続したまま保持する。他の操作ボタン・画面外の演出は差し替え、既存のイベント登録を重複させない。経路が欠けた場合やタイトル・交代画面では全体を再生成する。新しい状態キャッシュは持たない。
- `boardView`：同一盤面に対する更新にも対応し、変更のあるタイルのボタン自体を保持する。完全な属性モデルと子要素を更新し、見えなくなった部隊の情報を残さない。言語・サイズ・リプレイのidentity変更時は全タイルを再生成する。保持は現在の盤面1つだけ。
- `boardFocus`：座標セレクターとroving tabindexをUIモジュールへ分離する。ポインター中にフォーカスを動かしたり、選択コマンドを二重発火したりしない。盤面イベントは既存の3つの委譲リスナーを維持する。

### 再実行

基準と変更後をそれぞれビルド・別ポートでpreviewし、同じ環境で次を各3組、変更前→変更後の順に実行する。必要なら `MINISTR_CHROMIUM=/usr/bin/chromium` を指定する。正式CIのVite／Playwrightとの差を測る場合は、別系列として記録する。

```sh
node scripts/browser-response-v143.mjs http://127.0.0.1:4190 final-before-1.json before 1
node scripts/browser-response-v143.mjs http://127.0.0.1:4191 final-after-1.json after 1
python3 docs/reviews/v1.4.5/summarize.py RESULT_DIRECTORY
```

[before1](v1.4.5/final-before-1.json)／[after1](v1.4.5/final-after-1.json)、[before2](v1.4.5/final-before-2.json)／[after2](v1.4.5/final-after-2.json)、[before3](v1.4.5/final-before-3.json)／[after3](v1.4.5/final-after-3.json) が全受入raw。最初の探索計測はCPUプロファイルと重なったため採否に使わず、6runを新規に測り直した。コンテナだけ保持した途中案ではフォーカス中のタイル置換が重くなったため、タイルボタンも保持する方式を採用した。[探索・起動失敗の概要](v1.4.5/diagnostics.json)。探索CPUプロファイルは高頻度samplingによる負荷を含むため、性能改善の数値には使用しない。
