# 日替わりチャレンジ候補条件の先後バランス評価（#230）

日付から決まる18通りの条件（サイズ3 × 海域3 × 標準／前線補給・工兵の2）に、先後（赤が先攻、青に後攻補償+2000G）の極端な偏りがないかを、CPU同士の対戦で評価した。

## 方法

- 実行コマンド: `npm run balance:compare -- --generated --sizes 16,20,24 --seas none,coast,ocean --seeds <seeds> --variants seeded,frontline --bonuses 2000 --matchups normal:normal --rounds 60`
  - `seeded` は標準生成（v2）、`frontline` は前線補給・工兵（v3）。日替わりが実際に使う `generateSymmetricMap` と同じ生成を通す。
  - ルールは現行（CURRENT_RULE_VERSION）、60ラウンドで判定勝ち。damage seed は戦域の戦闘seed（`scenario`）。
- 3回に分けて実行した（生データは同じディレクトリの JSONL）。
  1. `2026-10-25-daily-balance-matches.jsonl`: seed `D20260101`〜`D20260104`、全18条件 × 4 = 72戦
  2. `2026-10-25-daily-balance-followup.jsonl`: 初回で赤0勝4敗だった `24/coast/seeded` に seed `D20260105`〜`D20260112` を8戦追加
  3. `2026-10-25-daily-balance-second.jsonl`: seed `D20260113`〜`D20260116`、全18条件 × 4 = 72戦
- 合計152戦。すべてのseedは実際の日替わりseed形式（`D<YYYYMMDD>`）。

## 除外基準と判断

- 事前に決めた基準: 条件ごとに8戦以上を行い、同じ側が7勝以上（87.5%以上）した組を「極端に不利」として導出表から除外する。
- 該当する組はなかったため、**導出表は18条件すべてを維持する**（`DAILY_TABLE_D1`）。除外した組はない。
- 一度公開した版（`d1`）の導出表は凍結する。将来、偏りが確認された場合は `d2` として別の表を作り、過去の日付を変えない。

## 限界

- 評価は CPU 同士（普通対普通）で、人間の赤軍とは異なる。人間にとっての難易度の差は測っていない。
- 1条件あたり8戦（一部16戦）で、統計的な有意性は主張しない。極端な偏りの有無を粗く確認する目的である。
- 日替わりは固定seedの1日1回の挑戦であり、同じ条件が数十日に一度しか現れない。条件ごとの詳細な調整は今回の範囲外。
