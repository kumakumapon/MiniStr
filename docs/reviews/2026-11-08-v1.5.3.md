# v1.5.3 ターン表示整合の確認

対象: #273。基準mainは `3b9bc8d58224c365a01ab51531aace1b08f653b4`（v1.5.2）。

## 変更範囲

- `ui/turnTiming`で期限・実効判定時期・残りラウンド・同点延長・キャンペーン推奨を共通表示。
- 判定時期は勝敗評価の`decisionRound`を使用。同関数は型だけを最小入力に広げ、実行時の処理は維持。
- 通常戦8作戦のタイトルと出撃前・対局中の表示を整合。期限付き作戦の正規化済み青軍生存条件は最終行動可能ラウンドとして表示。
- 本来の生存目標は開始境界を明記。キャンペーン推奨は評価の目安として期限と区別。
- 記録済みシナリオ・旧ルール・保存snapshot・リプレイ命令は変更しない。

## 検証

### ローカル参照環境

- lint・整形・テストを含む型チェック・build・リンク検査が成功。
- 全単体1,627件／164ファイルが成功。最初はbashを起動する3件がsandboxのEPERMで失敗したため、テストを変更せず全件をsandbox外で再実行した。
- 修正版配布UI67件／10ファイルが成功。英語の拠点数表示に日本語が残った初期版を修正し、再実行した。並走時のタイムアウトは成功扱いにせず、単独の再実行で確認した。
- Firefoxのタイトル／英語UI23件が成功。追加6件は日英×1280／390幅、統合戦術ON／OFFのタイトル→出撃前→対局、40ラウンド期限、推奨22／期限50のキャンペーンを確認する。スクリーンショットで期限説明と横幅を確認した。物理端末の確認ではない。
- ローカルの依存は旧参照環境（Vitest3.2.7／Vite6.4.3）。現行lockのクリーン導入・監査・coverage・Node22.13・通常の全3ブラウザ・地形33回は正式CIを合否基準とする。CI設定、閾値、retry、権限、Pages条件は変更していない。
- Chromiumは未導入で取得先が通信制限による403。配置済みWebKitもlibgtk-4等の共有ライブラリ不足で起動できなかった。これらをブラウザ成功として数えていない。

### 回帰とCodeQL

- 共通表示の18件、タイトル表示追加1件、既存勝敗境界・保存・リプレイ検証を利用。通常8作戦、全カタログ、訓練、生成、日替わり、カスタム、キャンペーン、旧ルール2／3／4・未指定を確認する。
- ルール3の40判定と現行60判定、カスタム75判定、最終ラウンド残り1、同点後の再判定、正規化された期限と通常生存目標の区別を確認。snapshotが表示で変化しないことも検証する。
- 初期のCodeQLは追加テストの`document.body.innerHTML`代入に1件のclient-side XSSを指摘した。HTMLを実行する必要のないテストなので、同じカードと期待値をHTML文字列として比較する形へ変更した。解析の抑制・除外は加えていない。
- 最終headの正式CI・CodeQLと監査の確定結果は[PR #274](https://github.com/kumakumapon/MiniStr/pull/274)と[Issue #273](https://github.com/kumakumapon/MiniStr/issues/273)へ記録する。途中の成功・失敗と最終headの結果を混同しない。
