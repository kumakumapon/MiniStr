# 峡谷の関門・湿地の突破の地点別評価

両戦域に3軍用・4軍用の独立した18×14配置を追加した。3軍は北・西・東、4軍は南を加えた順で表記する。地点によって道路・隘路・中立拠点までの経路が変わる。全員の初期部隊・資金・所有施設数と勝利条件は共通。通常2軍は従来の個別作戦を使用する。

## 短期CPU戦

CPU v7・普通・均衡で全軍敵対。調整用seed 33501では峡谷3軍の最初の12対局で北0勝だった。工場・峠の進路を調整し、南側2軍の出発位置を近づけた配置で北5／西3／東4。配置を固定してから別のseed 33509で以下を評価した。各陣営のIDと地点の割当を変えた2組を、3軍全6手番・4軍全24手番・戦術OFF／ONで比較した。既存の緑の国境は固定割当で同じ手番と戦術を比較した。合計300対局。各表の勝率の分母はその行の対局数で、順列は同じseedの対照条件。独立した乱数試行としての勝率推定には使えない。

集中攻撃は同じラウンドに、同じ軍の部隊が異なる2軍以上から、異なる方位の通常攻撃を受けた場合に1回と数える。攻撃元と標的の座標差の大きい軸で東西南北を決め、同差は東西とする。反撃・移動による接近は含めない。最初の脱落が起きなかった対局も母数に含める。全対局が自然決着または規定の期限判定で終わり、打切り・引分は0。

3軍では東の勝率が峡谷67%、湿地75%。西は峡谷の戦術OFF、湿地の戦術ONで各0勝。4軍も峡谷は西、湿地は東に勝利が偏った。次回は新しい種を用意し、地点別の占領経路と集中攻撃を比較する。CPU比較は人の思考時間を含まない。人間1軍で20〜30分という目標は実機の有人試遊で測る。[戦術別の集計・最初の工場占領](asymmetric-battlefields/validation.json)

## 再現と回帰

`npx vite-node scripts/asymmetric-assessment.ts validation 0 1` は各条件につきJSONを1行出力する。調整用は `training` を指定する。末尾の2値は0始まりの分割番号と分割数。保存検証では配置版・地点割当から初期盤面を再構築し、従来どおり全命令を照合する。通常2軍の2操作開始、非連番の参加軍、地点交換、途中保存、再生・再戦の初期状態、地形・配置の差し替え拒否を回帰検査に含めた。開始前のプレビューに部隊は表示しない。
