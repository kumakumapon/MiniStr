## 音声復帰の確認条件

初回操作前はcontextを作らない。visibilitychange／focus／pageshowは有効化済みplayerのrecoverだけを呼ぶ。Web Audioのstatechangeで遅れて発生するinterrupted／suspendedも再開する。背景中やclosedは再開しない。再開に失敗しても次の実操作で再試行できる。ミュート・音量0・終了済み戦闘曲は維持し、効果音の過去イベントを再発行しない。

ブラウザ回帰は実contextをsuspendし、背景状態・復帰イベントを模擬して再開を確認する。OSによる実際のアプリ中断や実機の出音確認とは区別する。


## CI初回の監査証跡・整形失敗

初回CI 41172269209では、新しい監査結果（全依存moderate12件／high0／critical0、本番0件）を保存したdependency-audit.jsonが整形検査で失敗。非空配列を含むJSON.stringifyの整形と既存Prettier規則が一致しないことが原因。監査の全値を保持したまま既存Prettier設定で証跡を書き出すよう修正し、配列入り報告の同値性と整形チェックを回帰化する。公開条件・権限・監査の失敗条件・整形対象を緩和しない。

監査の12件は開発依存minimatchのGHSA-g3hv-75wg-m249とESLint／typescript-eslintへの推移的な連鎖。公開ゲームの利用者への影響が確認されたという意味ではない。依存を自動で古いmajorへ戻すfixAvailableは採用せず、詳細と再評価条件を依存レビューと#168へ記録する。

### 再現

クリーンな基準／候補のcheckoutで正式lockfileから導入し、以下を同条件で実行する。調整用は `--seeds v122-tune --sizes 16,32 --seas none,coast --matchups normal:normal --policies balanced:balanced,defensive:offensive --damage-seeds scenario --max-games 16` に置き換える。不採用のtrial1/2は基準に同梱patchを適用する。trial2の追加比較はv12ゲート版 `trial2-v12.patch`、調整比較は元版 `trial2.patch`。それぞれヘッダーdigestと照合する。旧ゲートも比較対象は規則v12のみで、公開実装はv12以降に限定した。

```sh
GITHUB_SHA=$(git rev-parse HEAD) npm run balance:paired -- --sizes 16,20,32 --seas none,coast,ocean --seeds v122-final3 --variants frontline --matchups normal:normal,normal:easy --policies defensive:offensive,balanced:balanced --damage-seeds 991 --rounds 90 --seconds 3600 --max-games 72 --output /tmp/v122-final.jsonl
```

調整16局×4条件、追加72局×2条件、最終72局×2条件、上級12局×2条件＝376局。追加条件は `v122-check1,v122-check2`／戦闘seed731、3サイズ×3海域×標準:標準／標準:初級×守勢:攻勢の往復。採否を見た追加条件を最終の未使用条件として数え直していない。

音声復帰の単体回帰、補給の合流・実補給、砲兵先行の実攻撃・旧ルール、監査証跡の整形回帰は成功。型・lint・整形・build・配布UI57件も確認済み。初回coverage実行中にソースとテストの変更が重なり、旧ルールモジュールと新しい砲兵先行テストが混在した失敗（v6の撤退手数と旧ゲートを含む）は最終結果と扱わない。この実行では既存のbash起動テスト3件もsandboxのEPERM、worker更新通知にtimeoutが発生した。固定ソースで単体を再実行中で、正式lockのcoverageとブラウザ回帰は最終CIを正とし、PR本文へ対象SHAと結果を追記する。
