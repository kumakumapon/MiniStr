# 大盤面の選択・ズーム応答改善（2026-10-29）

対象PR #250、関連 #168・#155。基準main `1eccdf9a22cd07f3b2a7bf31379fb109e1f3d1f9`。最終headのCI／監査／CodeQL結果はPR本文へ記録します。

## 負荷の確認

Chromium CPU profileの上位に、全画面再生成後のcaptureRenderScroll復元callbackとrenderが現れました。callbackのscrollLeft／scrollTop代入がレイアウト確定を伴う経路です。また、tile.onclickはact内のrender後にfocusBoardPositionでもrenderを呼んでおり、通常の選択で全画面が2回置換されていました。ズームでも全タイル・パネルを再生成していました。プロファイルの標本数を正確な処理時間の割合とは扱いません。

## 実装

- 選択時はactによる1回の描画を使い、フォーカス復元のための2回目を除去。クリック前に復元対象を設定し、架橋確認・生産メニューへのフォーカス遷移を尊重します。Escapeの重複描画も除去。
- 通常対局／リプレイのズームはboardZoomViewで盤面のgrid寸法・viewport最大高・倍率表示・上下限ボタンを更新。タイル・viewport・イベントハンドラーを保持し、所有権・霧・射程等の状態は更新しません。
- 古い非同期focus ticketはrenderGenerationで無効化し、既存のスクロール／フォーカスポリシーを適用。ビューが未完成なら通常描画へ戻ります。CPU観戦の追従ズームは従来の描画経路を使用します。
- キーボード移動、50〜200%の上下限、手動倍率、オート倍率、タイトルとの共有、ホットシートを維持。対局規則・保存形式・CPU重み・版番号・素材・公開権限／条件の変更はありません。

## 回帰と記録

- helper単体で寸法・倍率・上下限・生きたラベル・タイル参照・ハンドラー・スクロール値保持、不完全なビュー／不正値での非更新を確認。
- 新規4ケースをChromium／Firefox／WebKitに追加。ja/en×1280/390で選択1回のroot置換、ズーム時のDOM保持、50/200%の境界、フォーカス、Escape／Enter／矢印による選択解除・移動、倍率維持・横幅を検証。固定時間による合否判定は追加しません。
- ローカルでは新規4件＋既存の倍率・拡大盤面・ホットシートを含む11件、前後測定24ケースが成功。代表的なPC／390pxの画像を目視確認。最新の依存・カバレッジ・全ブラウザ・Node22.13互換性は最終CIで確認し、結果をPR本文へ保存します。
- 全画面の初回表示や1回分の選択描画は残ります。CPU観戦の追従・実機iPhone/iPad・さらに長い対局等の計測は後続とし、今回の測定から保証しません。
