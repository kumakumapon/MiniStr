# 広域マップと先後バランス調整

組み込み11マップを18×12〜22×16に拡大した。通常戦の地形・所有拠点・初期部隊は回転対称とし、中立拠点や突破口を複数に分散した。峡谷・都市の従来の非対称配置も解消した。

後攻だけが初手前に航空機・艦船の燃料を支払っていた処理を新ルール4で修正。スコア戦は両軍の手番後に判定し、双方が目標以上なら高得点側の勝ち、同点なら続行とした。通常戦の outpost / industrial から後攻の自動期限勝利を取り除いた。大きい盤面でも両軍の合計が既存の対話プレイ上限128を超えないよう、新ルールは片側最大64部隊とする。

CPUの左上優先の同点処理を両軍で同じ向きに揃え、生産IDも数値順にした。戦闘部隊は中立施設を歩兵に譲り、敵司令部・視認した敵へ進む。これにより拡大時に部隊が中立施設へ集中して止まる問題を解消した。

再現コマンド:

```sh
npm run balance -- --maps skirmish,islands,canyon,siege,river,industrial,outpost,marsh,admiralty --rules modern --difficulty normal,hard --seeds 4 --rounds 60
```

## 互換性と検証

- セーブ/リプレイのコンテナは従来のschema 4を維持。旧ルール2/3は元の燃料・生産上限・スコア判定で再現する。
- 旧小型マップを履歴として保持し、スナップショットのない旧データも初期状態が完全一致する場合だけ当時の定義へ復元する。全11マップの旧セーブ・リプレイと改ざん拒否を回帰テストした。
- キャンペーンは既存のID・解除順・進行形式を維持し、拡大に合わせて評価目安を調整。上陸は26ターン、防衛は20ターン。通常戦への移行で outpost の期限を廃止した。
- lint、format、テストを含む型検査、565件のカバレッジ付きテスト、build、リンク検査が成功。CPU計測との同時実行で30秒を超えた2件は、計測終了後にworker数2で同じ条件の全テストを実行し成功した。タイムアウトや検査条件は変更していない。
- システムのChromiumで既存E2E35件が成功。最終調整後の拡大盤面・手番交代・CPU操作4件も再確認し成功。PC1440×1000 / スマートフォン390×844の拡大都市マップで、両軍の移動、スクロール、保存・再開、ページ幅とスクリーンショットを確認した。Firefox/WebKitは今回未実施。

盤面の拡大と経済補償により対局の展開は変わる。今後の実戦で調整する場合は、マップ・先後・難易度を記録し、同じシード条件で比較する。
