# v1.5.22 評価記録

任意の参加軍、途中の担当変更、固定チーム、水域マップ、3軍配置・4軍手番・CPU終盤を対象とする。[仕様](../multifaction-v2.md)・[実装と正式CI（PR #321）](https://github.com/kumakumapon/MiniStr/pull/321)。通常2軍の主要77ファイルは前版と同じblobである（[照合](v1.5.22/two-army-unchanged.json)）。

## 公平性の比較

主比較はseed152201、3軍の全6／4軍の全24初期手番順、戦術ON/OFFの60条件。v1.5.21の配置・CPU v5・20Rと、新配置・CPU v6・3軍21R／4軍20Rを同じseed・初期順で比較した。複数の仕様をまとめた版間比較であり、一つの変更だけの効果ではない。[旧版60条件](v1.5.22/baseline.json)・[新版60条件](v1.5.22/compact.json)。

| 条件         | 旧：第1／2／3／4軍の勝数 | 新：第1／2／3／4軍の勝数 |
| ------------ | ------------------------ | ------------------------ |
| 3軍・戦術OFF | 1／4／1                  | 1／4／1                  |
| 3軍・戦術ON  | 0／1／5                  | 1／2／3                  |
| 4軍・戦術OFF | 5／7／5／7               | 6／6／6／6               |
| 4軍・戦術ON  | 7／5／7／5               | 6／6／6／6               |

主比較は診断・採用判断にも使用した。最初の候補では北0勝が残り、北の開始域・工場位置と公開施設数を使う優先相手を限定変更した。3軍は全21Rで各手番位置7回、4軍は全20Rで各5回を担当する。初期手番位置による勝数まで均等になったという意味ではない。

最終候補を固定してから、調整未使用seed152204／152205で120条件を実行し、結果から再調整しなかった（[全結果](v1.5.22/holdout.json)）。3軍OFFは1／11／0、ONは0／6／6。4軍OFFは12／12／13／11、ONは13／11／13／11。3軍北側の戦術ON・追加seedでは0勝が残る。配置・CPUの公平性の完了とは扱わない。主比較・追加seedは全て短期判定まで進み、最後の1軍になる自然決着を保証する評価ではない。

追加の前哨基地強襲・交差海峡は2／3／4軍、個人戦／固定チームを12回、最終engineで確認した（2軍の個人戦と1対1チーム戦は同条件）（[全結果](v1.5.22/maps.json)）。これは開始・進行・終局の確認であり、同盟や水域の戦力バランスの十分な評価ではない。

## 旧未決着26条件

v1.5.20の従来規則・CPU v3で400Rまで未決着だった全26条件を、同じseed・順・難易度・方針でCPU v6へ比較した。上限は400R／65,536命令。20条件が86〜289Rで決着し、6条件が400Rの上限に達した（[全行・trace・状態hash](v1.5.22/legacy-comparison.json)）。比較対象外の既決着条件が全て改善したとは主張しない。旧保存のCPU版は自動変更しない。

残る条件は `holdout-orders-15152-2/11/13/20`（生存2軍）と `settings-152003-0/2`（生存3軍）。後者は生存2軍からの司令部進軍規則の対象外でもあり、別途診断する。

最初の `orders-152001-0` は旧CPUを400Rまで再現し、公開済みの21,777命令traceと最終状態hashに一致した（[再現](v1.5.22/diagnosis.json)）。200〜400Rでは、燃料内の占領目標があるのに帰還する候補は0回だった。戦車・APCが占領できない敵施設を目標に集まり、近い施設を往復していた。CPU v6では、生存2軍・40R以降の非占領部隊を敵司令部へ向ける。

同じ400Rの検証済み盤面から100Rずつ継続した対照比較では、旧CPUは追加4,284命令後の500Rでも未決着、CPU v6は930命令・423Rで第2軍が勝利した（[対照比較・初期の滞留部隊](v1.5.22/stalemate-continuation.json)）。最初からの比較でも16,895命令・289Rで決着した。

## 測定対象の再現性

個人戦の主比較・追加seed・旧26条件は、味方施設の補給を軍別に直す前のengineで測定した。付録の[小差分](v1.5.22/measurement-engine.patch)を最終engineへ適用すると測定engineをbyte単位で再構成できる。変更された味方施設への対応付けは個人戦では恒等写像であり、これらの条件の処理結果を変えない。

最終engineでも最初の旧未決着例を全対局再測定し、16,895命令のtraceと最終状態hashが一致した（[照合](v1.5.22/final-engine-check.json)）。水域・チーム12条件、保存継続、旧再現・対照継続は最終engineで測定した。[測定元のhashと照合範囲](v1.5.22/measurement-provenance.json)を残し、異なる測定元を同じものとして記載しない。

## 保存互換・操作

旧保存の16条件は、512命令のprefix、保存状態、次64命令、最終状態、履歴情報、保存容量を含む既存行データがv1.5.21と完全一致した（[全行の照合証跡](v1.5.22/legacy-continuation.json)）。新schema6の16条件は各64命令まで進行し、途中の担当変更を保存・読込後、各128命令、計2,048命令の続きが一致した（[全結果](v1.5.22/schema6-continuation.json)）。

新規則では任意軍と各盤面、回転手番・100R停止・脱落枠のスキップ、味方への攻撃・操作禁止、チーム判定、架橋・破壊・渡河を含む全履歴、担当変更と不正履歴拒否を単体で検証する。現在の担当を変更しても旧CPU・過去の命令・残り行動を変えない。

PC1280px／モバイル390px、日英、キーボード、旧3軍20R保存の再開・再戦、第2／第4軍の任意参加、途中切替・引渡し・JSON再開、水域3／4軍の10ブラウザ試験がローカル補助環境で成功した。橋の向きの表示は追加2件でも確認した。スクリーンショットはPlaywright成果物へ保存する。

ローカルはNode24.19、TypeScript5.9.3／Vite7.3.6／Vitest3.2.7／Playwright1.63とシステムChromiumによる補助検証。jsdomの導入はregistryが403で拒否し、古いgz fixtureの欠落もあるため、固定依存の正式判定はPR/main CIで行う。lint・format・型・リンクを確認し、既存の試験・skip方針・CI権限・時間上限・公開条件は変更しない。
