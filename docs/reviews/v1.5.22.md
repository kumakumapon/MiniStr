# v1.5.22 評価記録

参加軍の自由指定、途中の担当変更、固定チーム戦、水域マップと、3軍配置・4軍手番・CPU終盤の限定改善を対象とする。通常2軍は独立した既存実装を保持する。[仕様](../multifaction-v2.md)。

## 比較手順

`multifaction-assessment.ts` は主比較seed152201（全6／24手番順、戦術ON/OFF）、追加マップseed152202、調整未使用seed152204/152205、v1.5.20で未決着だった従来規則の全26条件を固定する。短期戦は3軍21R／4軍20R、従来規則は400R／65,536命令を上限とする。全履歴のtrace・最終状態SHA-256、打切り、CPU時間と実行環境の制約を記録する。

主比較は配置・CPUの診断と採用判断にも使用した。北側0勝の候補をそのまま採用せず、北の開始域と工場位置、公開施設数を使う優先相手の選択を限定変更した。未使用seedは最終候補確定後に実行し、その結果から再調整しない。

## 旧未決着の診断

旧最初の条件orders-152001-0をCPU v3で400Rまで再現し、公開済みtrace・最終状態hashと完全一致した。終盤に燃料内の占領目標があるのに帰還した候補は0回だった。戦車が占領できない敵施設へ集まり、近い施設間を移動して停滞していた。CPU v6は生存2軍・40R以降の戦闘部隊を敵司令部へ向ける。同じ400R盤面からの診断継続では23R・930命令後に第2軍が勝利した。最初からの比較では289Rで決着した。全26条件の結果は比較完了後に集計する。

## 保存互換と自動試験

旧保存継続16条件は、512命令のprefix、保存状態、次64命令、最終状態、履歴情報、保存容量を含む既存の行データがv1.5.21と完全一致した。新仕様では任意軍・各盤面、手番交代、同盟攻撃禁止、チーム判定、架橋と破壊の全履歴、担当変更と不正履歴拒否を単体で検証する。

ローカルはNode24.19、TypeScript5.9／Vite7／Vitest3／Playwright1.63とシステムChromiumを使う補助検証。固定依存での正式判定はPR/main CIを用いる。ローカル全node試験は1,380件が成功したが、旧gz fixtureの欠落、sandboxのbash生成拒否、同時評価による時間切れがあった。長期保存4件は単独再実行で成功した。ローカルjsdom導入はregistryが403で拒否したため、DOM試験は正式CIで確認する。試験のskip・時間上限・CI権限・公開条件は変更しない。

PC1280px／モバイル390px、日英、キーボード、通常2軍から独立した開始、旧3軍20R保存の再開・再戦、任意の第2／第4軍、途中切替・引渡し・JSON再開、水域3／4軍と固定同盟をブラウザで検証する。スクリーンショットはPlaywright成果物へ保存する。

公平性の完全保証、物理端末での20〜30分達成、視認性・操作応答・長期の実戦評価は継続する。固定チーム・水域は初版であり、動的同盟、潜水艦・潜航、途中参加・退出、任意の地形編集・生成は別の拡張とする。従来32盤面は旧規則・CPUのまま再開し、改善版CPUは明示的に切り替える。
