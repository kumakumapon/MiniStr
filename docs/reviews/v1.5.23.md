# v1.5.23：バトルシーンと表示設定

## 原因と修正範囲

2軍は `battleSceneForCommand` からモーダルを表示していたが、4軍の `onCommit` は短い行動表示と汎用効果音だけを呼び出していた。また、4軍のエンジンは軍別状態へ戻す際に一時的な2色投影の戦闘イベントを保存しないため、確定後の保存状態だけから待伏せ・反撃を推定すると情報が不足する。

2軍の戦闘要約抽出を `combatSummary.ts` に移し、4軍も同じ確定戦闘から要約を得る。従来の `applyFourArmyCommand` の戻り値は維持し、UI専用の `applyFourArmyCommandWithCombat` だけが一時的な要約を追加で返す。反撃・同時射撃・待伏せ・武器・HPは実際に解決した投影から取得し、軍の脱落処理より前の撃破を保持する。演出のために再戦闘・乱数消費は行わない。要約は保存・Worker観測・チェックポイントに入れない。

4軍の演出は盤面の再描画とは独立したモーダルとし、背景の操作を止める。CPU・自動再生は閉じるまで待機する。スキップは継続し、一時停止・開始条件・画面離脱・読込・視点変更・担当変更は演出と保留音を解除する。1手送りでも戦闘を表示し、離れた位置への再生シークでは途中の戦闘をまとめて表示しない。制限視点は前後の観測で両部隊を識別できる場合だけ表示し、端末交代中は表示しない。

## 設定・互換性

`ministr.battleScene.settings` に2軍用 `twoArmy` と複数軍用 `multiArmy` の真偽値を保存する。初期値は両方ON。片方の変更で他方を上書きせず、不正JSON・型・余分な項目・過大入力は採用しない。保存不能時も現在の画面には反映する。バックアップの許可項目と検証にも追加した。既存のバックアップは設定がなくても利用できる。新設定を含むバックアップの復元にはv1.5.23以降を使う。

対局のschema・engine・経路・CPUの版、勝敗・戦績、命令列と乱数の規則は変更しない。演出OFFでは追加の演出待機・再描画を行わない。2軍の非戦闘の戦術演出は対象外。

## 検証

公開済みv1.5.22のエンジン本体を取得し、変更していない依存モジュールへのimport先だけを現在の作業環境へ向けて比較した。旧CPU v1／v3／v4／v5と現行v6、engine2〜5、旧広域・小型3／4軍・新小型3／4軍・水域の9条件×128命令、計1,152命令で、演出付き経路と前版の各命令後の状態が一致した。[比較記録](v1.5.23/engine-compatibility.json)に条件・版・命令数・状態／trace hashを保存した。旧広域4条件のprefixには戦闘がなく、小型・水域5条件では計87戦闘を含む。この比較を長期決着・公平性の再評価とは扱わない。

- 新規の確定戦闘・設定テストに、通常／同時射撃、待伏せ、脱落時のHP、制限視点、第3・4軍の表記、キャッシュを利用した1手再生、バックアップ・不正設定を含めた。
- モーダルの単体検証は、時間切れ・スキップ・一時停止・メニュー・表示OFF・画面解除・Escapeで待機と音が一度だけ解除されること、フォーカスと背景の操作可否を確認する。
- 実ブラウザーはPC1280px／スマホ390px、日英、2軍と複数軍のON／OFF保存・再開、確定HPと同じ戦闘結果、1回だけの命令適用、CPU待機・取消、4軍の再生を検証する。`systems-two-battle-*`、`systems-four-battle-*` のスクリーンショットをCI成果物に残す。
- ローカル補助環境はNode24.19・TypeScript5.9.3・Vite7.3.6・Vitest3.2.7・Playwright1.63／system Chromium。固定依存とJSDOMの取得制限があるため、固定依存での全unit・配布UI・3ブラウザー・カバレッジ・Node22.13の正式結果はPRとmain CIで確認する。検査のskip、時間上限、CI権限・Pages条件は変更しない。

## 開発用依存の指摘と公式撤回

開発用picomatch 4.0.7の [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) は、実装中の2026-11-18 15:38:56 UTCに公式データベースで撤回された。[公式変更](https://github.com/github/advisory-database/commit/7bee34adc2028ebd00c2e87fe43e432cd134fe40)と[開発元の参照コメント](https://github.com/micromatch/picomatch/pull/235#issuecomment-6315749381)を照合した。修正版が公開されたわけではなく、公開版は引き続き4.0.7である。

公開準備中に実装した期限付き例外とその設定・判定・テストは、正式公開前にすべて削除した。最終版の監査スクリプトはv1.5.22と同一で、all／productionの両方を実行し、生の結果を保存し、high／critical・取得失敗・不正な報告を従来どおり停止する。監査のskip・allowlist・期限付き緩和・開発依存の除外は含めない。npm側への反映は最終CIの新しい監査で確認し、その実測結果をPRとReleaseへ残す。

撤回は危険な正規表現／globが高速化したことを意味しない。MiniStrの配布物は静的ファイルで、保存JSONやゲーム操作をpicomatchへ渡さない。開発用サーバーを公開せず、信頼できないglob設定・パターンを開発ツールで実行しない運用を維持する。

## 公開検証環境の限定修正

公開検証では新しいAWS上のUbuntuランナーの地域別ミラー `us-east-2.ec2.archive.ubuntu.com` が既存の切替対象から漏れ、139MBの依存取得に約18分を要し、最初のCI第1分割が30分の上限で中断した。地域別EC2ホストも既存のHTTPSミラーへの置換対象に追加した。配布スイート・署名鍵・優先順位・無関係なパスを保持し、複数地域と各APT形式・反復実行を回帰検証する。ジョブの上限・テストの件数や時間制限・署名検証・公開条件は変更しない。正式な完了結果は、この限定修正後のソースとmainのCIで確認する。
