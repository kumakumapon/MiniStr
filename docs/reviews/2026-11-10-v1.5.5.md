# v1.5.5 護衛失敗の再現・限定修正

## 基準と原因

基準はv1.5.4/main `0f016e46bdff2e896f3592b4c4784efe8dd10386`。convoy-escort・標準ON・seed15422・赤hard/青easyを再実行し、T16の`objectiveLost`（r1喪失、命令添字382）を再現した。

最初の判断差はT9・命令添字191。r1は自軍首都(0,9)でHP35、資金4500・収入2000があり、さらに20修理できる。しかし`moveAction`は守勢方針でしか修理待ちを呼ばず、`defensiveServiceWait`も全任務対象を除外していた。このため均衡方針の対象は修理を1回受けただけで(2,5)へ出発する。

## 最終修正と不採用案

製品コードは`src/ai/recovery.ts`と`src/ai/rules.ts`だけを変更した。既存の`usesMissionSafety`で保護するv14統合戦術ONの護衛対象の地上補給車について、守勢以外でも既存の修理待ちを使えるようにする。HP50未満、自軍の適合拠点、有償修理可能、未行動、搭載なし、観測済みの直接射撃合計がHP未満という条件は維持する。脱出可能な場合の即時脱出を優先する。

修正後は命令191が`wait r1`となり、次の手番までにHP55へ回復、T18にr1がHP50で脱出して赤勝利となる。[再現要約](v1.5.5/reproduction.json)を保存した。初期状態・全命令・最終状態のgzipはローカル保持とし、リポジトリには追加しない。

健康な対象まで一律に護衛を残す試作は、seed15241・15412の既存勝利を悪化させたため不採用。移動後の被害上限を先に適用する試作も、必要な退避を止めてT6に対象を失うため不採用とした。既存の護衛順・相対危険度・退避の扱いには変更を残していない。修理中の安全判定は既存の観測済み直接射撃であり、全ての移動後攻撃を保証する判定ではない。

## 対局比較

Node24.19.0の型除去と[v1.5.4の拡張子解決loader](v1.5.4/native-typescript-loader.mjs)で実際のCPU/ゲームコードを実行した。各JSONL先頭にgame/AIソースとharnessのSHA-256、上限、seed方針を記録している。これは正式なVitest・型検査・ブラウザー検証の代替ではない。

| ---------------------------------------- | ---: | -------------- | ---------: | ---------------: |
| 26作戦×OFF/標準ON、hard:easy             |   52 | 46→46          |         52 |                0 |
| 4任務×既知4seed×4難易度                  |   64 | 54→55          |         63 |                0 |

既知seedは15241/15411/15412/15422、未使用は15511/15512。最終候補を固定してから未使用結果を開き、その後のCPU調整は行っていない。変更は対象の15422・護衛hard:easyだけ。15241のT23達成、15412のT13達成、撤退3任務を維持した。以前から残る敗北も記録しており、全任務の成功率を保証しない。

[全比較一覧](v1.5.5/comparison.json)、各before/afterのJSONL（結果・命令ハッシュ）、[harness](../../scripts/cpu-escort-v155.ts)を保持する。全命令gzipはローカルに保持し、同じharnessから再生成できる。圧縮データのGitHub追加は自動承認レビューに拒否されたため実施していない。非対称の任務なので、赤達成数を一般的な先後勝率として扱わない。再現例（beforeは基準コードで実行）:

```sh
node --no-warnings --loader ./docs/reviews/v1.5.4/native-typescript-loader.mjs scripts/cpu-escort-v155.ts after known output/known.jsonl
```
