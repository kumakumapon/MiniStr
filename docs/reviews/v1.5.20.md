# v1.5.20 確認記録

[採用仕様](../four-army-play-support.md)。開始・軍別観測・可逆操作・復旧・終局に関するUIと保存を拡張し、既存のゲーム規則・CPU判断は変更しない。

## CPU評価の固定条件

`npm run four-army:fairness -- <shard> <shards> <output.json>` で再現する。条件は実行前に固定し、CPU v3／v4と従来／拡張規則の4組を同じseed・手番順・設定で対比較する。

- 未使用seed152001の全24手番順：96条件。
- 公開済みv1.5.16のCPU v3未決着20条件：80条件。従来規則のv3は公開済みtrace／最終盤面SHA256と照合する。
- 未使用seed152003で、難易度／方針と手番を4回転する混合設定：16条件。512命令で保存し、復元後の64判断・状態を比較する。

主集計は400ラウンド／65,536命令上限、計192条件。上限によるongoingは打切りとして保持し、引分へ変換しない。観測勝率と、未決着すべてがその軍の勝利になった場合までの区間を併記し、勝利数だけで公平性の完了を宣言しない。旧未決着群の拡張規則＋v4で400ラウンドを超えた条件は、別枠で1,000ラウンドまで診断する。異なる予算の結果を同じ勝敗表へ混ぜない。

ゲーム／CPUの実装は公開済みmain `2cc327434042f8f5a35bb44d939fbf399613ef31` を基準とし、5つの規則・観測・CPUファイルのSHA256を実行報告へ記録する。新規則やCPUの調整を測定途中に行わない。

同じseedの回転条件は独立した確率試行とは扱わない。区間は打切りの帰結の範囲であり、統計的な信頼区間ではない。軍ID別と開始手番別を両方示し、規則の差とCPU版の差を混同しない。fallbackの補助診断は各主群の最初の固定条件 `orders-152001-0` を再実行し、主測定の命令列・最終盤面SHA256と一致した場合だけ採用する。

長い測定は、引数5に完了済み報告（protocol・gameSource・frozenSources・rows）を渡して再配分できる。条件・source・重複を検証し、未完了分だけを既存のshard数へ分ける。今回は146条件を保持して残り46条件を再配分した。同期実行中の旧Vite-nodeは終了シグナルだけで止まらず、対象を確認して強制終了した。再配分後に完了した旧側の行は重複照合に使い、主集計へ二重計上しない。実行途中で中断した条件は初期状態から再実行する。

## 操作と保存の確認

軍別の観測から履歴を作り、不可視位置・搭載相手・敵の準備・未来の命令を公開しないことを検証する。schema4の参照は完全履歴と照合し、構造が正しくても未観測の参照を拒否する。手動2枠と自動枠のバックアップ復元、不正データ拒否、書込権再確認、他タブ競合、容量不足と取消後の遅延応答を検証する。

配布bundleでPC1280px／390px・日英、4担当軍の操作とCPU区間、undo後の分岐保存、偵察後のundo拒否、手番開始の自動保存、原本書き出し・独立削除、全体終局と個別脱落の表示差、同条件再戦を確認する。スクリーンショットはE2E成果物の `v1520-support-*`。短い自動操作を、物理端末での人間の長期対局の代替とは扱わない。

## 実行環境と公開判断

ローカルの補助検証はTypeScript5.9.3・Vite7.3.6・Vitest3.2.7・Playwright1.63／システムChromiumを使う。固定依存の正式CIとは区別する。ローカルにjsdomと一部の過去gzip記録がないため、DOM単体・完全checkoutの検証は正式CIを根拠とする。依存・lockfileの依存版、CI／Pagesの権限・閾値・timeout・retryは変更しない。

正式CIの全件結果、対象SHA、CodeQLとPagesは実装PR／Releaseを参照する。mainと同一SHAの検証済み成果物と実際の配信版を照合してからtag／Releaseを公開する。

初回PR CIでは単体1,908件・配布UI67件・E2E749件が通った直後に、一方のjobが30分の上限へ到達した。FirefoxとWebKitが片側へ集中し、E2E部分が20.3分対12.2分だったため、Chromiumを両エンジンの間に並べ、両枠にChromiumを含む既存2分割へ変更した。新しい保存・undo・再戦の4件をFirefox／WebKitにも追加した後の757件について、変更前後の全テスト識別子が一致することを[dry-run記録](v1.5.20/browser-shards.json)で照合した。件数・assertion・timeout・retry・worker数・公開条件は緩和しない。変更後の[PR CI](https://github.com/kumakumapon/MiniStr/actions/runs/43733331598)は単体1,912件・配布UI67件・E2E757件が成功した。ブラウザー枠の実行時間差は残っており、分割の負荷・準備時間の分離計測は運用上の継続項目とする。

## ブラウザー分割の限定修正

最終差分の[CI 43736485842](https://github.com/kumakumapon/MiniStr/actions/runs/43736485842)では第1枠381件が成功し、第2枠がjob全体30分の上限へ達した。ブラウザーの並び順だけではWebKitの負荷が片側へ残るため、既存の `--shard=n/2` を各ブラウザーに個別適用するrunnerへ変更した。

既存の2枠に、Firefox113/112件・Chromium156/151件・WebKit113/112件を配分し、合計382/375件＝757件を実行する。変更前の全テスト識別子と照合し、重複・欠落がないことを確認した。各ブラウザーの画像／トレースは別ディレクトリへ保持し、どの子プロセスが失敗・中断してもjobを失敗させる。全ブラウザーを実行し、失敗したテストを再試行して通す処理は追加しない。

通常実行とカスタムproject／config／reporter指定は元のPlaywright呼出しを維持する。CIのNode標準チェック22件（既存15＋runner7）で、失敗伝播・全ブラウザーの実行・空の探索結果の拒否・出力先の分離を確認する。`.github`、公開条件、job上限30分、テスト上限30秒、worker数、retry、既存assertionは変更しない。[全件の識別子照合](v1.5.20/browser-shards.json)。

旧20条件の従来v3は公開済みの命令列・最終盤面SHA256を全件再現した。従来規則のv3／v4は全48組で命令列・最終盤面が完全一致し、旧挙動の退行は検出しなかった。再配分中の重複6本も一致し、主集計から除外した。拡張規則の48組では全組の命令列が変わり、26組で勝者が変わった。拡張v3でも旧20条件が決着したため、解消をv4単独の改善とは扱わない。

軍ID別の勝利が揃っても、手番別の差は残る。新24順の拡張v4は4/12/4/4、旧20では4/4/0/12だった。旧20は過去の打切りから選んだ集団であり、一般の勝率は表さない。従来の新24順では各軍5/24勝、未決着を含む可能範囲は各軍20.8〜37.5%。少数seed・回転条件から公平性を保証しない。

fallbackは主比較全体で5,090回。[固定代表2条件の再実行](v1.5.20/fallback-diagnosis.json)では27回／25回とも生産施設の占有による拒否だった。各12件の記録例は観測上許可され、実状態では未観測部隊が占有していた。既存のCPUは視界外生産の優先を下げ、既知の部隊行動後に試みる。却下後は秘密情報を使って代案を探さず、待機／手番終了とする。代表2条件の診断を全5,090回の原因と断定しない。

各対局の1判断p95は11.17〜63.96ms。同一ホストの並列測定・負荷変動を含む補助値で、物理スマートフォンの操作応答を保証する値ではない。拡張v4の旧未決着群には400R後の打切りがなく、条件付き1,000R延長は0件。1,000Rを実行済みとは扱わない。

## schema4の保存継続

[混合設定16条件の完全記録](v1.5.20/save-continuation.json)で、512命令後のschema4保存・全履歴検証・読込・軍別観測履歴の再生成を照合した。復元前後で各64命令、計1,024命令の判断・状態・RNGが一致した。保存サイズの最大は59,354bytes。この64命令内のfallbackは0回で、拒否時も照合を短縮しない経路は専用単体テストで確認する。旧schema3側の同条件64判断とも命令hashが一致した。

再実行は `npm run four-army:save-continuation -- audit.json`。fallbackの代表再現は `npm run four-army:fallback-diagnosis -- classic-v3.json expanded-v4.json diagnosis.json` を使う。

## 次の対応

1. 従来規則の400R打切り26条件と開始順の偏りを、接敵・生産・燃料帰還・司令部到達の段階別に診断する。拡張戦術OFFも対照に加え、原因を絞って新CPU版で限定改善し、旧版の再生を維持する。複数の新seedで再評価する。
2. 物理PC／スマートフォン、実時間2／4時間、支援技術・長期メモリ・保存容量を人間操作で確認する。今回の全4担当軍・日英・PC／390pxの自動操作とは区別する。
3. G2の2〜4軍参加数、G3の途中人間↔CPU切替の順で、手番・視界・保存の仕様を決める。水域／港、同盟、複数人undoなどは個別採用とする。
