# v1.4.0の仕様・比較・公開前確認

Issue #213、PR #256。基準はv1.3.0 `51bfe19bc2cfc09288374c886e93bdde37d3a61a`。
計画のみのcommit `49934ebb83c2f07b2f441fd8a192541d3ae4203c` でドラフトPRを作成してから製品変更へ着手した。

## 仕様

[リリースノート](../releases/v1.4.0.md)に実装範囲・数値・制約を記載。通常戦／単体作戦を優先する選択式の統合戦術で、天候は視界、ZOCは視認済み地上兵科から開始する。各案を一括で既定化せず、snapshotの有効項目で独立評価できる。

移動は指令受付時の観測から経路を固定し、実際の最初の占有接触で停止。準備済みの敵による合法な待伏せは1回のみ。ZOCで先に停止した場合は実接触を満たさず、待伏せは発射しない。降車自体も待伏せの対象にしない。隠れた接触で降車が不成立なら、搭載を保って行動を消費し、接触相手を当該陣営へ公開する。

潜航艦の通常視界と探知は分離。CPU・移動候補・脅威・盤面・情報欄・履歴・イベント演出へ反映し、未検知部隊を可視マスだけで露出させない。発砲／物理接触の公開は公開対象側の手番終了で解除する。潜航継続は最大3回の自軍開始、入港で浮上し、隠れたまま港で修理しない。

## 比較方法

`npm run balance:tactics -- --profiles classic,transport,base,combined --layouts original,revised --cpu baseline,adapted --sizes 16 --seas none,coast --seeds v140-example --rounds 60 --max-games 64 --seconds 1200 --output balance.jsonl`

- classic: v12、従来の移動・降車。transport: 移動後降車を有効にしたv13の標準。
- base: v13の観測経路・会敵・情報公開と移動後降車、有効項目はすべて無効。simultaneous／ambush／terrain／weather／zoc／submarinesや `weather+zoc` 等で個別・組合せを比較。
- combined: 6項目を有効。original／revisedで元／改訂snapshotを分ける。
- baseline CPUは現行の合法予測を使う旧判断、adaptedは価格×有効HP損失・新行動・移動後降車を理解する判断。赤は常に先攻、復路で配置を回転して軍方針を交換。色と先後は独立ではない。
- 地形・戦闘・天候のseedを記録。未決着は勝利・引き分けと分け、raw全件とソースdigestを残す。対CPUの局・往復は独立標本として数えない。

- 初期の12ラウンド診断24局は不正指令なし、全局未決着。動作確認であり公平性の根拠には使わない。

## 固定した実装と評価範囲

ゲーム／CPUの評価ソースは `74489182f75cab9394419b6df25685d81084e028` で固定し、`src/game`・`src/ai` の非テストソースと生成比較の共通実装のdigestは `d8f7acade4fef5fe585c7009269d96432ed7ef6b269e21c4d1d6a4a96f680a95`。その後の変更はテスト・表示・比較ハーネス・記録で、評価対象のゲーム／CPUは変更していない。

比較は標準難易度、最大60ラウンド、固定した戦闘seed、往復で実施。往復は幾何配置の180度回転で、赤先攻を変える実験ではない。軍方針は往復で交換する。単純な地形対称性や、異なる方針の勝敗合算から先後の公平性を結論しない。

生成条件の最終確認は `v140-finalA/B`、個別・組合せは `v140-factorC`、数値比較は `v140-numericD`、32盤面は `v140-wideE`、20盤面の軍方針は `v140-policyF`。開発初期の `v140-tuneA` とは分離した。ただし、複数のルール・CPU・配置で同じ条件を繰り返すため、全局数を独立した標本数として扱わない。最終条件を見てさらに調整し、同じ条件を未使用と呼び直すことはしていない。

### 再実行

基本形のコマンドは前節を参照。固定前半のハーネスは上記commit、カタログ比較追加後は `776b4901be388cd985beafa7bc244c607e8fd77e` を参照。ハーネスの各版のhashはraw先頭へ保存。後半では生成条件と別に公開カタログのID、実寸、配置・初期部隊・位置付き目標を回転できるようにした。ゲーム／CPUのソースdigestは前後一致している。

- `--initiative 0,3,5` は同時射撃の攻撃側補正を比較する。通常presetは3%。待伏せにはこの補正を付けない。
- `--profiles base,terrain --plain-cover false` で補正なしC0と山岳だけC1、`--profiles terrain,combined --plain-cover true` で平原にも+5ポイントを付けるC2を比較。C2は通常presetに採用していない。
- `--profiles base,simultaneous,ambush,terrain,weather,zoc,submarines,weather+zoc,weather+submarines,zoc+submarines,weather+zoc+submarines` は機能の個別・ペア・3項目結合を比較する。
- `--catalog skirmish --profiles classic,combined --layouts original,revised --cpu baseline,adapted --damage-seeds 1411,1417 --rounds 60 --max-games 32 --output catalog.jsonl`。islands／tundraも同条件。公開済みのカタログ定義自体は変更しない。tundraは非対称の防衛任務なので任務達成として別記し、先後の公平性に合算しない。他の作戦は全23作戦の8ラウンド合法指令テストで別途確認する。

### 計測項目と限界

中立拠点到達・占領・初回収入・生産・増援到着は半手番（赤1、青2、次の赤3）で記録。損耗金額は被害を受けた軍ごと、撃破金額・実際に保存された手番更新の修理費・弾薬・待伏せの準備／発射／失効／取消、潜航・探知エピソード／探知した潜水艦数、降車・不成立、雨ラウンド・最大部隊数を残す。終局判定前の最後の手番更新に修理費が発生した場合も、その保存状態の実費として数える。

CPU所要時間は並行するローカルテストの影響を受ける診断値。操作応答改善の前後比較や、実機性能の保証には使わない。未決着は勝利／引き分けに数えず、途中中断もcomplete=falseで保持する。ソナー探知と通常の地形視界を分離し、失探した潜航艦の移動先を演出で公開しない。索敵履歴には最終確認位置を残し、ソナーによる再確認なしに「そこにいない」と断定しない。

## 途中の失敗と修正

- 最初の製品CIは1,436件成功／1件失敗。主武器欄へ副武器名を重ねて表示した不具合を修正した。
- 次のCIは全単体成功、Node22.13・CodeQL・WebKit反復も成功したが、AI coverageのstatements97.73%／branches95.44%が既存98%／96%基準を下回って失敗。支援攻撃の逐次HP・不成立条件と、攻撃を優先して潜航しない判断を追加検証した。閾値・対象・既存テストは維持。
- ローカル配布UI57件の初回は、通常戦の新規開始と訓練の従来規則を混同した期待値2件が失敗。新規通常戦v13／訓練v12の契約を明示して修正。対象9件は再実行で成功。
- ブラウザの初回20件では、snapshotの格納キーを取り違えたテスト4件が失敗（16件成功）。`scenarioSnapshot` の実保存を確認するよう修正し、20件、英語名称・自軍潜航を含む24件、追加戦闘8件がそれぞれ成功。PC／390幅のスクリーンショットも確認した。

## 最終の比較結果

全10バッチ **440局／570,826指令**を完走（全rawのcomplete=true）。不正指令・指令予算超過・時間切れなし。待伏せ25回、潜水艦の攻撃225回、成功した降車1,864回。ブロックされた降車はこのCPU比較では0回で、橋上の未探知潜航艦との接触・行動消費は専用の回帰テストで確認した。

[全raw・再実行コマンド・SHA256・条件別集計](v1.4.0/summary.json)。rawの勝者赤／青は記録上の陣営であり、下記の異なる規則、方針、非対称任務の合算を公平性の値として扱わない。

### 生成16盤面：同方針・同難易度

各行は2seed×内陸／沿岸×往復の8局。表は先攻赤：後攻青（引き分け・未決着とも0）。

| 規則／マップ                   | 旧CPU判断 | 対応CPU判断 |
| ------------------------------ | --------- | ----------- |
| 従来v12／元配置                | 3：5      | 3：5        |
| 従来v12／改訂配置              | 3：5      | 3：5        |
| 移動後降車のみ／元配置         | 3：5      | 2：6        |
| 移動後降車のみ／改訂配置       | 3：5      | 3：5        |
| 新しい会敵の共通基盤／元配置   | 5：3      | 4：4        |
| 新しい会敵の共通基盤／改訂配置 | 3：5      | 4：4        |
| 統合6項目／元配置              | 5：3      | 4：4        |
| 統合6項目／改訂配置            | 2：6      | 5：3        |

従来v12の指令digestは同じ条件の旧／対応CPUで全件一致し、旧ルールへの新しい戦術判断の混入を確認しなかった。統合時は元配置5：3→4：4、改訂配置2：6→5：3。CPU対応で変わる一方、改訂配置が常に元配置より公平という結果ではない。元カタログを保持し、改訂配置を選択した統合戦術のsnapshotとして分離する。

この条件の中央値では、元／改訂・従来／統合とも中立到達は半手番赤1・青2、占領3・4、収入5・7。対称地形でも最初の行動・収入の時間差は残る。32盤面の占領8・9、収入10・11も同様。増援の中央到着は32盤面で元9・9、改訂8・9。経路変更は到着を変え得るが、初回収入の差を解消したとは結論しない。施設収入・生産価格・先後補償は据え置き。

### 個別機能・相互作用

11条件×元／改訂×内陸／沿岸×往復＝88局。base、戦闘3案の各単独、天候／ZOC／潜航の各単独・全3ペア・3項目結合を同一条件で実行した。結果はrawで条件ごとに保持。天候は同一ラウンドを両軍共有しても、天候切替後の初動は先攻が先に行うため、その事実だけで公平とは扱わない。ZOCは未視認敵を候補計算へ入れず、雨で通常視界が狭まってもソナー距離は維持する。

### 数値の比較と採用値

同じ数値比較seed・沿岸、元／改訂×往復の各4局、対応CPU。

| 条件                   | 先攻：後攻 |
| ---------------------- | ---------- |
| 同時射撃のみ、攻撃側0% | 2：2       |
| 同時射撃のみ、3%       | 3：1       |
| 同時射撃のみ、5%       | 1：3       |
| 統合、0%               | 4：0       |
| 統合、3%               | 3：1       |
| 統合、5%               | 2：2       |
| 地形補正C0（追加なし） | 4：0       |
| 地形補正C1（山だけ）   | 3：1       |
| 地形補正C2（山・平原） | 2：2       |
| 統合C2（山・平原）     | 4：0       |

攻撃側補正と先攻の勝率は単調な関係にならず、C2も統合時には偏りが拡大した。採用値は小幅の3%／山だけ+5ポイント（上限45%）とし、既定の平原・森・道路の役割を保持する。最適性が確定した値ではなく、タイトルで選べる初版の設定値として継続評価する。数値比較は旧CPU条件も含め、initiative48局・C0/C1追加16局・C2追加16局を保存。

### 32盤面・軍方針・公開カタログ

32×32の沿岸／多海域×元／改訂×往復で各8局。従来2：6、移動後降車3：5、統合5：3。統合の元配置は2：2、改訂は3：1。海域・兵站・配置による差が残る。

20盤面・沿岸で元／改訂×往復、各4局。同方針の守勢同士は従来4：0→統合0：4、攻勢同士は2：2→4：0。混合の守勢対攻勢は両規則とも攻勢4勝・守勢0勝。規則によって偏りの向きが変わり、守勢の対攻勢改善はこの条件では未確認。長期の協調・守勢評価は#213で継続する。新たな補償金をこの少数条件へ合わせて追加しない。

カタログは各行4局（戦闘seed2つ×配置往復）、同方針・同難易度。

| マップ／規則／配置     | 旧CPU判断 | 対応CPU判断 |
| ---------------------- | --------- | ----------- |
| 緑の国境／従来／元     | 2：2      | 2：2        |
| 緑の国境／従来／改訂   | 1：3      | 1：3        |
| 緑の国境／統合／元     | 2：2      | 2：2        |
| 緑の国境／統合／改訂   | 3：1      | 2：2        |
| 群島補給線／従来／元   | 4：0      | 4：0        |
| 群島補給線／従来／改訂 | 4：0      | 4：0        |
| 群島補給線／統合／元   | 4：0      | 2：2        |
| 群島補給線／統合／改訂 | 1：3      | 2：2        |

群島の元配置で従来4：0→対応CPUの統合2：2、改訂も2：2を確認した。緑の国境は従来の元2：2、改訂1：3に対し、統合・対応CPUはともに2：2。各4局の限定した結果であり、全カタログの公平性を保証しない。凍土の防衛線は非対称の生存任務で、全32局が赤の任務達成。先後勝率へ合算せず、他の任務・追加の戦闘seedでの評価を後続とする。

## ローカル確認

- 固定ゲーム／CPUで全単体1,477件／141ファイルとcoverageが成功（既設Vitest3.2.7による補助結果）。後から追加した潜航とエディタ／全体観戦の回帰も別途成功。正式lockfileでの件数・coverage・最終ブラウザ結果はCIを参照する。
- 配布UI57件／9ファイル成功。新規通常戦v13、訓練v12、既存日替わりv12、旧保存／再生の区別を維持。
- PC／390幅・日英で新操作24件、戦闘8件成功。最終の全体観戦切替を含む36件を再実行し、CIでもChromium／Firefox／WebKitに組み込む。
- lint・format・テスト込み型・build成功。ローカルの既設依存と正式lockfileの差はCIで確認する。実機iPhone／iPadは既存方針どおり低優先度・未実施。

ブラウザの全体観戦テストでは、操作禁止の盤面ボタンをクリックした初回ケースがtimeoutとなった。観戦用の「部隊へ移動」から潜航艦を選ぶ実際の導線へ修正し、日英・2幅の4件が成功。盤面の操作禁止は維持した。
