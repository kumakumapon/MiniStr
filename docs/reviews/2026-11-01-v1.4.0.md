## 仕様

[リリースノート](../releases/v1.4.0.md)に実装範囲・数値・制約を記載。通常戦／単体作戦を優先する選択式の統合戦術で、天候は視界、ZOCは視認済み地上兵科から開始する。各案を一括で既定化せず、snapshotの有効項目で独立評価できる。

移動は指令受付時の観測から経路を固定し、実際の最初の占有接触で停止。準備済みの敵による合法な待伏せは1回のみ。ZOCで先に停止した場合は実接触を満たさず、待伏せは発射しない。降車自体も待伏せの対象にしない。隠れた接触で降車が不成立なら、搭載を保って行動を消費し、接触相手を当該陣営へ公開する。

潜航艦の通常視界と探知は分離。CPU・移動候補・脅威・盤面・情報欄・履歴・イベント演出へ反映し、未検知部隊を可視マスだけで露出させない。発砲／物理接触の公開は公開対象側の手番終了で解除する。潜航継続は最大3回の自軍開始、入港で浮上し、隠れたまま港で修理しない。

## 比較方法

`npm run balance:tactics -- --profiles classic,transport,base,combined --layouts original,revised --cpu baseline,adapted --sizes 16 --seas none,coast --seeds v140-example --rounds 60 --max-games 64 --seconds 1200 --output balance.jsonl`

- classic: v12、従来の移動・降車。transport: 移動後降車を有効にしたv13の標準。
- base: v13の観測経路・会敵・情報公開と移動後降車、有効項目はすべて無効。simultaneous／ambush／terrain／weather／zoc／submarinesや `weather+zoc` 等で個別・組合せを比較。
- combined: 6項目を有効。original／revisedで元／改訂snapshotを分ける。
- baseline CPUは現行の合法予測を使う旧判断、adaptedは価格×有効HP損失・新行動・移動後降車を理解する判断。赤は常に先攻、復路で配置を回転して軍方針を交換。色と先後は独立ではない。
- 地形・戦闘・天候のseedを記録。未決着は勝利・引き分けと分け、raw全件とソースdigestを残す。対CPUの局・往復は独立標本として数えない。

## 検証の進行

- 初期の12ラウンド診断24局は不正指令なし、全局未決着。動作確認であり公平性の根拠には使わない。
- 調整条件・最終条件の結果と正式CIは実装・確認完了後に追記する。
- ローカルのネットワークはnpm registryを許可しておらず、offline clean installはcache不足で失敗。既設Vitest3.2.7等による確認は補助結果とし、lockfileのVitest5／TypeScript6／Vite8による正式ゲートはGitHub CIで確認する。
- 旧キャンペーン攻略・旧リプレイの回帰、異常な潜航・準備・天候・公開情報の保存入力、日英操作・演出・CPU指令を追加確認する。
