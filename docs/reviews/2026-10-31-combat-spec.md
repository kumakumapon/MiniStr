# 戦闘3案の仕様・比較評価（v1.3.0 / Issue #213）

## 目的と範囲

隣接戦闘の同時攻撃、視界差による奇襲、山・平原・道路の防御効果をまとめて評価する。v1.3.0での対象は仕様化と評価であり、ゲーム規則への導入は比較結果・旧データ互換性・CPU対応をそろえて判断する。

現行は規則v12。攻撃後の実際の残HPから反撃を計算し、攻撃で撃破された部隊は反撃しない。射程・武器・残弾・間接攻撃による制限もある。防御星は山4・平原1・道路0で、1星につき満HPで10%軽減、HPに比例して低下する。既に地形差があるため、その量の調整として評価する。

## 案A: 隣接時の同時攻撃

- マンハッタン距離1の直接攻撃が対象。攻撃側・防御側とも同一の戦闘開始時HPから損害を計算し、同時に適用する。
- 防御側は直接反撃用の合法な武器・射程・残弾を必要とする。間接攻撃には反撃しない。防御側がこの攻撃で撃破される場合も、有効な同時射撃は成立し、相討ちを認める。
- 攻撃側の主導権は攻撃ダメージ×1.05を比較用の初期値とする。両軍同じ武器・HPでも完全同値にはならない。5%は公開用の確定値ではない。
- 両軍とも実際に射撃した武器の弾薬を1回だけ消費。攻撃側の行動を消費。乱数は攻撃、合法な同時反撃の順に各1回使用し、撃破で反撃乱数を省かない。
- 損害・撃破・経験・勝敗は両側の損害確定後に評価する。予測と演出は同じ計算を使い、「同時射撃」と表示できるようにする。

## 案B: 視界差と奇襲

### 今回比較した最小モデル

攻撃確定直前の視界を使い、防御側から攻撃者を視認できない場合は反撃を認めない。攻撃で発見されても同じ戦闘では反撃を再許可しない。攻撃側には通常の目標視認・射程・弾数の制約を適用する。

現行は隣接すると通常は互いを視認できるため、隣接戦闘にこの条件を加えるだけでは要望の「視界外での会敵時の一方的な被弾」は生じにくい。比較用の最小モデルと、移動に対する自動反応は区別する。

### 会敵時の自動反応を導入する場合の仕様案

- 移動開始前から敵が移動部隊を視認し、移動部隊側から敵を視認できない場合を候補とする。実際の接触位置まで移動を解決してから、合法な直接射撃の可否を判定する。
- 片側だけが見えている場合の反応とし、双方未視認では自動攻撃を発生させない。移動側の同一戦闘中の反撃は認めず、解決後に通常の視界を更新する。
- 1移動指令あたり反応は最大1部隊。複数候補はID順など保存・再生で安定した規則にする。射程外・弾切れ・搭乗中・間接武器は反応不可。
- 同一守備部隊の反応は1ラウンド1回とし、通常攻撃とは別に使用済み状態を記録する案。弾薬を消費する。復帰・取り消し・保存再開で回数が戻らないよう、新規則の状態と検証が必要。
- 通過途中の反応で移動を終了し、撃破時は残りの経路を実行しない。CPUも公開情報から移動リスクを評価し、未発見の敵位置を予測・ログで露出しない。

自動反応は追加の状態・経路イベント・CPU判断を要するため、今回のCPU比較モデルには実装していない。モデルの勝率を自動反応の有効性や安全性の証明には使わない。

## 案C: 地形防御

- 地上部隊への追加補正として、比較案は山+1星（合計5）、平原+1星（合計2）、道路0を維持する。進入可否・移動コストは現行を維持。
- 森・都市・工場・港・首都・補給所・陣地の既存効果は保持。陣地を含む既存値に上記追加分を加える。山に入れない車両へ山の効果を付与しない。
- 航空・艦艇には追加補正を付けない。既存の防御計算・経験・装甲・武器相性・乱数は保持する。間接攻撃にも被攻撃側の地形軽減を適用する。
- 同時射撃では各部隊の開始HPと所在マスで個別に軽減。奇襲を受けても地形による軽減は残す。

## 評価方法と再現

`scripts/combatExperiment.ts` は評価専用。製品のgameモジュールはこのファイルをimportしない。`scripts/prepare-combat-experiment.mjs` が基準v1.2.2の別worktreeを作成し、forecastと実際の反撃解決を一緒に変更する。同時攻撃の予測だけ変更して、実戦は逐次反撃のまま比較することを防ぐ。

```sh
node scripts/prepare-combat-experiment.mjs /tmp/ministr-combat-sim simultaneous
cd /tmp/ministr-combat-sim
GITHUB_SHA=experiment-simultaneous npm run balance:paired -- --sizes 16,20,32 --seas none,coast --seeds v130-combat --variants frontline --matchups normal:normal --policies defensive:offensive,balanced:balanced --damage-seeds 2903 --rounds 90 --seconds 3600 --max-games 24 --output /tmp/combat-sim.jsonl
```

profileはclassic / simultaneous / ambush / terrain / combined。別seed確認は16/32・陸地/海洋・seed v130-combat-check・戦闘seed6113・同方針組合せの往復16局。各profileとも両条件を実行し、raw・digest・結果と制限を保存する。CPUは基準v1.2.2を固定し、予測に応じて合法な指令を選び直す。v1.3.0のCPU調整についても別の前後比較で評価する。

## 導入判断の条件

先後・赤青・方針・難易度・海域・兵科ごとの偏り、待ち合い、損失と補給負担を比較する。平均勝率だけでは採用せず、守勢悪化や特定地形への集中を記録する。人間の公平感は別評価とする。

採用する場合は新しいゲーム規則版を設け、旧セーブ・シナリオ・記録済みリプレイは旧計算を保持する。CPU・戦闘予測・演出・音・ログ・説明を同期し、相討ちの勝敗、射程外、弾切れ、低HP、視界更新、反応の回数制限、乱数の消費を回帰化する。現行規則へ上書きしない。

## 比較結果と採否

各profile40局（調整条件24＋別seed確認16）、計200局。すべて決着し、違法指令なし。各条件で赤青を交換した往復を含み、200個の独立標本ではない。全体の先後勝数には軍方針違いも混ざるため、均衡方針同士20局と守勢対攻勢20局を分ける。

| モデル | 全40局の先攻:後攻 | 均衡同士20局の先攻:後攻 | 守勢:攻勢20局 |
| --- | --- | --- | --- |
| 現行 | 19:21 | 8:12 | 3:17 |
| 同時攻撃（主導権+5%） | 20:20 | 9:11 | 1:19 |
| 攻撃前の視界による反撃制限 | 19:21 | 8:12 | 3:17 |
| 山・平原の追加防御 | 21:19 | 9:11 | 4:16 |
| 3案の組合せ | 19:21 | 8:12 | 3:17 |

- 同時攻撃は全体20:20だけを根拠に採用しない。守勢は3→1勝に悪化し、既存CPUの攻撃安全差・補給・消耗評価を再調整する必要がある。
- 視界制限だけのモデルは現行と40局すべての指令digest・勝敗が一致。この条件では実際の会敵反応を追加した評価にならない。自動反応は上記の別仕様を実装してから評価する。
- 地形案の守勢3→4勝は小標本での改善。山5星・平原2星の全作戦や全兵科での採用根拠には不足する。森林等との地形差や防御待ちの影響も追加評価する。
- 組合せは均衡の先後8:12・守勢3:17で、この標本の現行を上回る効果は確認できない。

**v1.3.0の判断:** 3案の仕様化・モデル比較を完了し、既定ルールへの一括導入は見送る。新しい戦闘規則版、実際の会敵反応と状態保存、CPUの消耗・攻撃順評価、予測・演出の同期を実装する際の設計・回帰・再評価条件として#213へ残す。v1.3.0は規則v12の戦闘計算・保存／リプレイを維持する。

[集計・各ファイルのSHA-256](v1.3.0/combat-summary.json)と同ディレクトリの全raw JSONLに結果を保存。CPUはv1.2.2固定でのモデル評価であり、v1.3.0の守勢調整後の全条件や人間の公平感を保証するものではない。時間値は並行実行と計測中の一時停止の影響を受けるため、CPU性能の比較には使用しない。
