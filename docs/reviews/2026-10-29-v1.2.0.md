## 実装状況

32×32生成・単体作戦、観戦ズームのDOM保持、追従時の重複スクロール削減、タイトル／準備画面の背後の盤面生成省略、サイズに応じたリプレイ保持上限、守勢CPUの連携攻撃を実装しました。全方針への攻撃緩和と補給距離変更の試案は既存作戦の回帰により不採用とし、旧ルールと均衡／攻勢方針を維持しています。

### 採用した仕様

- 生成サイズへ32×32を追加。既存16×12／20×16／24×20の生成方法は維持。標準・前線補給／工兵・3海域、生成条件共有、保存／再開に対応し、生成作戦は60ターンで判定します。
- 単体作戦「広域戦線32」は180度回転対称の地形・配置、前線工場と補給所、各軍9部隊、開始6,000G・後攻補償2,000G。補給所2か所の所有で20点、敵司令部占領、全滅で決着し、90ターン終了時にも判定。前線へ初期配置して開幕の移動を短縮します。
- 観戦ズームは盤面DOMを保持。中央へ移動する直前の古いスクロール復元を省略し、座標→部隊と輸送車→搭乗者を索引化。タイトル・作戦準備・キャンペーンメニューの背後のタイル生成を省き、対局へ戻る表示位置を保持します。
- リプレイの保持上限は最大32、合計8,192セル相当を目安とし、32×32は初期地点を含む8個。返却状態の複製・巻き戻し・観測情報の境界を維持します。
- 守勢CPUが射撃可能な味方との即時追撃と対応修理施設からの有利な交換を追加。最小ダメージで追撃成立を見積もり、最大反撃で撃破される追加攻撃は採用しません。行動済み・射程外・移動済み砲兵は支援に数えず、仮想移動や未観測敵を使いません。

均衡／攻勢の判断、旧ルールの判断、先後補償を維持。対局ルールv12、対局／リプレイschema4、キャンペーン進行schema5は変更せず、CPU改善は再開後に新しく選ぶ指令へ適用します。過去リプレイは記録済み指令を再現。32×32の新しい共有リンクはv1.2.0以降を必要とし、旧アプリは未対応サイズとして拒否します。

## 観戦・表示の計測

[全raw値・環境・bundle／スクリプトdigest](v1.2.0/spectator.json)。同じLinux環境、Node24.19.0、既設Vite6.4.3／Vitest3.2.7／Playwright1.62.1とシステムChromiumで比較。正式lockfileはCIで別途検証。変更前・後を交互3回、各2回warm-up＋30標本、他のCPU対局やテストを止めて計測しました。各runのnearest-rank p50の中央値（ms）を示します。

| 盤面／幅 | 観戦部隊への移動 前→後 | 観戦ズーム 前→後 | タイトル再表示 前→後 |
| --- | ---: | ---: | ---: |
| 16×16／1280px | 71.7 → 66.4 | 66.7 → 40.5 | 165.2 → 125.0 |
| 32×32／1280px | 148.3 → 120.7 | 145.2 → 51.2 | 252.5 → 123.7 |
| 16×16／390px | 65.6 → 66.6 | 64.1 → 32.5 | 146.3 → 119.9 |
| 32×32／390px | 129.3 → 125.1 | 131.6 → 50.2 | 228.5 → 119.9 |

32盤面のズームは約62〜65%、タイトル再表示は約48〜51%短縮。部隊への移動はPCで約19%、狭い幅では約3%で、小盤面では改善していません。全raw値・p95・最大値も保存しており、中央値だけで上限時間を保証しません。CPUを停止し、native handlerから2frame待機までを計測。自動追従と同じ中央移動の経路を使いますが、CPU計算込みの連続観戦FPSを測ったものではありません。

初回readyは各run1回の計3観測のみ。32条件の中央値はPC522.6→466.3ms、390px479.1→453.5ms。作戦開始は207.9→202.3ms／214.3→233.6msで、狭い幅では遅くなっています。全体の起動高速化を断定せず、背後の不要な生成を省く効果と操作を開始した際の遅延生成を区別します。

## 長期リプレイの保持メモリ

[全raw値](v1.2.0/retention.json)。同一ハーネスで前→後を順に測定。2,000指令のリプレイを保持したままタイムラインを生成・6地点へseek・解放し、各段階で明示的GC。5cycleの初回をwarm-upとした4値の中央値です。

| 盤面 | 保持heap bytes 前→後 | 解放後差分 bytes 前→後 | 6回seek合計 ms 前→後 |
| --- | ---: | ---: | ---: |
| 16×16 | 342,804 → 343,620 | 9,360 → 10,048 | 94.7 → 91.1 |
| 32×32 | 727,656 → 327,124 | 14,512 → 17,132 | 151.4 → 227.2 |

32盤面のタイムライン保持量は約55%減少し、離れた位置へのseek合計は約50%増加。保持上限と再計算のトレードオフです。既存の16盤面を維持し、32盤面での保持量を優先して採用。追加回帰では破棄後の過去／未来seekを逐次再生と照合し、返却状態の変更が内部へ戻らないことも確認しています。

ファイル本体・指令配列を保持したままの追加heapであり、アプリ全体のメモリではありません。GC後にも小さな差分は残り、ブラウザの長時間リーク不存在の証拠にはしません。任意の指令長に対する総メモリ上限も今回の保証対象ではありません。

## CPU比較と採否

`scripts/paired-balance.ts`でサイズ16／24／32、3海域、通常／前線生成、複数seed、先後と配置方向を交換。赤が常に先攻で、復路は難易度・軍方針を交換し180度回転します。後攻2,000G、ルール12、60ラウンド、1手番120指令上限を維持。全指令の合法性、決着・指令digestを保存。CPU対局を並行した実行の判断時間は性能比較には使用しません。

最初の試案は全軍方針への攻撃緩和と補給距離変更を含みました。守勢の勝数が増えても既存の分岐攻略・撤退に回帰が出たため不採用。補給距離を戻し、追加攻撃を守勢・現行ルールだけへ限定し、最大反撃での生存条件を追加しました。既存の攻略テストを変更せず再確認しています。

調整にTune-A／Tune-Bを使い、Verify-C／Verify-Dで試案を確認。その後の採用版は別のHold-E／Hold-Fで評価し、最後に実装コミットを固定して再実行しました。[集計・全ファイルの一覧](v1.2.0/cpu-summary.json)に全538局分を保存。往復・変更前・不採用試案・再実行を含み、独立標本538件ではありません。変更前には32生成だけをbackportし、旧CPUを保持しています。

| 標準難易度・攻勢対守勢 | 16サイズ 守勢勝数 前→後 | 24サイズ | 32サイズ | 合計 |
| --- | ---: | ---: | ---: | ---: |
| 調整seed・通常生成（各12局） | 2 → 3 | 1 → 0 | 0 → 2 | 3/36 → 5/36 |
| 未使用seed・前線生成（各12局） | 2 → 2 | 1 → 1 | 0 → 3 | 3/36 → 6/36 |

広域の守勢を改善した一方、調整用24サイズは1勝減り、全体でも攻勢優位が残ります。全条件で守勢が強くなったという結論にはしません。未使用seedの16／24を維持し、32の改善と既存攻略の回帰解消を根拠に限定採用。先後補償や全方針の重みは一括変更しません。

- [調整前](v1.2.0/training-before.jsonl)／[採用版](v1.2.0/training-after.jsonl)：均衡36局は先攻21・後攻15。サイズ別は9:3／7:5／5:7で、全36局の指令digest・勝敗・理由・ターン・指令数が変更前と一致。小盤面の先攻偏りも記録します。
- [未使用seed前](v1.2.0/validation-before.jsonl)／[採用版](v1.2.0/validation-after.jsonl)：36局すべて決着。不採用の広い試案は別のVerify-C/Dで守勢5→2勝と悪化し、攻略回帰もあったため採用していません。途中確認の採用版72局も保存し、最終再実行の指令digestがすべて一致しました。
- [32サイズの難易度・戦闘乱数24局](v1.2.0/difficulty.jsonl)：3海域×Difficulty-G×戦闘乱数1／4294967295×上級:標準・標準:初級×往復。上級9対標準3、標準6対初級6。先攻13・後攻11、全滅2・60ターン判定22。32で難易度差が常に保たれるとはいえず、判定比率と標準対初級の差は後続評価に残します。
- [新作戦10局](v1.2.0/wide-front.json)：戦闘乱数7／73、均衡同士・上級/初級交換・攻勢/守勢交換。すべて合法指令で15〜26ターンに支配点で決着。均衡2局は先後1勝ずつ、上級は初級に4勝、攻勢3対守勢1。長い90ターン上限まで待たず中央目標で進行することを確認しました。
