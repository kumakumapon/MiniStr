# 複数軍の後続拡張：確定仕様と受入条件（v1.5.25）

この文書は、途中参加・潜水艦・動的同盟を後続版で実装するための仕様である。v1.5.25ではゲームへ有効化しない。通常2軍、従来広域、既存の小型対局・固定チームの規則と記録を維持する。

## 適用範囲と実装順

1. 途中参加の初版は、既存の生存軍の人間／CPU担当交代を利用する。これはv1.5.22から提供済み。未参加軍を新設する参加・参加軍の退出は、以下の別契約で実装する。
2. 潜水艦は交差海峡の新規対局から導入する。通常2軍の潜水艦と共通の能力・行動・探知を使用し、軍別観測を接続する。
3. 動的同盟は新規対局で明示的に有効化したローカル対局へ導入する。固定チームの途中編集とは分離する。

任意地形・生成盤面、通信対戦、資金／部隊の譲渡、同盟の勝利後の継続戦は初版に含めない。これらの採用には別の盤面・通信・勝敗仕様が必要である。

## 途中参加・退出

- 担当交代は生存する参加軍だけを対象とし、現在の資金・部隊・残り行動を引き継ぐ。交代のたびに保留Workerを取り消し、undoを消去し、端末引渡しと自動保存を行う。
- 新規軍追加は開始時に参加予約を設定した新規対局だけで有効にする。最大4軍、各軍は1回だけ参入できる。脱落軍の復活、旧対局への予約の後付け、通常2軍への軍追加は禁止する。
- 予約には軍ID・参加可能ラウンド・開始区域・司令部・初期部隊・資金・所属チームを記録する。予約区域と参加条件は全員に公開し、未参加時の部隊・視界・収入・行動を作らない。
- 参入は全生存軍が行動を終えたラウンド境界で処理し、次ラウンドから手番へ入る。過去分の収入・補給・手番を与えない。開始処理は1回だけで、定常燃料の免除はその軍の最初の手番だけとする。
- 区域や司令部を他軍が占有している場合は参入を保留し、公開された理由を表示する。敵部隊の非公開位置を理由文・配置候補・プレビューで明かさない。強制移動・撃破・資金返却の例外処理は行わない。
- 退出は人間操作をCPUへ委ねる「離席」と、軍そのものが脱落する「降伏」を別操作にする。離席は従来の担当変更で処理する。降伏は自軍の手番で確認後に予約し、次の境界で通常の脱落・中立化処理を1回だけ行う。未参加の予約取消では生存軍を変更しない。
- 既に確定した終局へ参加・降伏・予約取消を適用しない。予約軍を待つことだけを理由に、最後の生存チームの勝利を保留しない。

## 潜水艦・潜航・対潜

- 能力値・費用・燃料・弾薬・水域移動・港での生産／補給は通常2軍の共通定義を使用する。複数軍だけの能力補正を作らない。
- 潜航／浮上は自軍の未移動・未行動の潜水艦だけが実行でき、両行動を消費する。潜航は外海だけで許可し、潜航後の自軍3回目の手番開始で浮上する。従来2軍の `dive` と同じ処理を軍別に適用する。
- 地形の可視性と潜航接触の探知を分離する。駆逐艦は距離3、潜水艦は距離2の対潜探知を持つ。攻撃等で明らかになった接触の保持と解除も2軍と同じ自軍手番境界で行う。
- 同盟では通常視界と、各味方が正規に得た潜航接触を共有する。探知していない軍へ非公開の潜航部隊・耐久・燃料・弾薬・潜航残り回数を渡さない。CPU・予測・盤面選択・音・演出・行動履歴・再生の全てに同じ観測を使用する。
- 駆逐艦の対潜武器と副武器の弾薬は共通武器定義を使う。未探知潜水艦への攻撃、占有マスを試す不正移動、生産失敗を使った接触探査を許可しない。失敗理由は未索敵の敵の有無を区別しない。
- 通常2軍と、潜水艦無効の旧複数軍対局は従来のユニット集合・武器・観測・演出を保持する。

## 動的同盟

- 全生存軍は常に、重複しない1つのチームへ所属する。同盟を有向関係として連鎖させず、同じチームの軍は相互に味方とする。
- 自軍の手番中に、既存チーム全体と他の既存チーム全体の合併を提案する。関係する全生存軍の同意が必要で、合併後も敵対するチームを最低2つ残す。全軍の合併を拒否し、同盟操作だけで即勝利しない。
- 脱退は自軍だけを新しい単独チームへ分離する。所属する他軍のチームを解散・変更しない。提案・同意・撤回・脱退は各軍1ラウンド1回まで、未決提案は1件までとする。
- 変更は次ラウンドの開始処理より前に、合意済み合併→脱退の順で確定する。同一境界で対象が変わった提案は無効にし、提案IDと理由を記録する。戦闘・補給・行動の途中で所属を変更しない。
- 境界で通常視界と接触共有を再計算し、同盟解除後は新しい敵の現在情報を表示しない。既に見た履歴は最終目撃情報として区別し、引渡し前の盤面や古い予測を残さない。資金・操作権・施設補給・搭載・部隊は軍別を維持する。
- 軍の脱落と勝敗はその境界の確定チームで判定する。最後のチームが勝利し、勝者一覧は終局時に確定して保存する。終局後の同盟変更や過去の仲間への勝利の付替えを認めない。
- CPUの初版は提案・同意・脱退を自動選択しない。CPU担当中の外交は現状維持とする。全軍人間の同意検証から始め、CPU外交は別の評価後に採用する。

## 保存・再生・互換性

- 規則・状態の形が変わる実装には新しい複数軍match／engine／ruleset／外側schemaを割り当てる。予定値はmatch3・engine6・four-army-v6・外側schema7。これらは仕様上の予約であり、v1.5.25の読込経路へ登録しない。CPU版は実装時に独立して割り当てる。
- 開始時の参加予約、当初のチーム、初期担当と、参入・降伏・外交・担当変更を発生順の1本の命令列へ記録する。ラウンド境界の確定順も規則で固定し、命令位置・発行軍・提案ID・変更前後を再検証する。
- 初期マップと全合法命令から状態・所属・生存軍・視界・勝者を再構成する。外部ファイルの最終状態やチェックポイントだけを信頼しない。二重参入、予約の無い軍、脱落後の操作、無同意の同盟、過去の所属と異なる操作を拒否する。
- 上限は当面65,536命令・8MB、全体バックアップ40MBを維持する。制御・外交イベントも同じ命令上限に含める。途中取消・進捗・自動保存・競合時の保護は従来の非同期検証へ接続する。
- 旧schema1〜6・CPU v1〜7・layout1〜3は当時の規則で継続する。新しい規則を旧保存へ自動適用しない。旧記録の条件を変えて遊ぶ操作は新規対局として分離し、原本と戦績を保持する。
- 未対応の将来版や新命令を旧版へ読み込ませたときは、状態変更・原本削除を行わず明示的に拒否する。仕様ファイルをゲーム保存として読み込む経路は作らない。

## 実装の受入条件

| 領域 | 必須の確認 |
| --- | --- |
| 参入境界 | 予約2軍＋参入1／2軍、満員・占有・予約取消・100R停止・同時脱落・終局直前。各軍の開始処理と収入が1回だけ。 |
| 操作と取消 | 人間／CPU交代、参入・降伏・外交の直前に保留Workerを作り、古い応答・再生タイマー・保留演出が適用されない。 |
| 潜航観測 | 全4軍の組合せ、探知距離の内外、味方の探知、同盟解除、攻撃後の露見・解除、港・浮上・燃料切れ。視界外のHTML・音・履歴・CPU入力を検査。 |
| 外交 | 全参加数、提案と全員同意、無同意・全軍同盟の拒否、撤回、同一境界の競合、脱退と脱落、終局の勝者固定。 |
| 保存 | 全境界の直前／直後で保存・全履歴検証・再開・再生し、その後512命令の命令列・状態・RNG・担当・所属・勝者が連続実行と一致。 |
| 不正入力 | 将来版、重複イベント、改変したチーム・予約・潜航状態、範囲外ID、サイズ上限を無書込みで拒否。破損原本の書出しが可能。 |
| 旧版退行 | 通常2軍・campaign、旧広域、小型layout1／2／3、固定チーム、CPU v1〜7の既存命令と継続結果が一致。 |
| 画面 | PC1280px／スマホ390px、日英、キー／タッチ、交代時の遮蔽、終局・再戦。スクリーンショットと実機試遊を区別して記録。 |

実対局への導入は、参入・潜航・外交を独立した変更として検証してから組み合わせる。v1.5.25では本仕様と、未対応入力を拒否する現行境界の回帰確認までを提供する。
