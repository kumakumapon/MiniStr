# 4軍参加対局 初版（v1.5.17）

## 対象

固定32×32「四方の前線」、4軍すべて敵対、ユーザーが任意の1軍、残り3軍がCPU。既存の各軍8部隊・資金10,000・搭載込み16部隊上限、脱落・最後の1軍勝利、100ラウンド区切り、CPU v3、経路規則1を継承する。通常2軍の戦績・キャンペーンには反映しない。従来の全軍CPU観戦も開始メニューから選択できる。

## 操作

1. タイトル「4軍対局・観戦」→「1軍を操作・敵CPU3軍」→担当軍、seed、手番順、CPU設定を選んで開始。
2. 自軍の部隊または施設を盤面で選択。矢印キーでもマスを選べる。参加対局は兵科記号を表示し、命令欄に部隊名・ID・HPと座標を表示する。
3. 移動、主/副武器攻撃、合流、搭載、降車は命令ボタン→枠で示す対象マス→「命令を確定」。矢印キーで移動後、Enterで対象を選べる。待機・占領・生産・手番終了も確認してから実行する。
4. 「取消」またはEscで未確定命令を破棄。実行済み命令の巻き戻しは提供しない。
5. 手番終了後に敵CPUを自動で進め、自軍の手番で停止する。開始時や再開時が敵手番なら「再生」でCPUを進める。「一時停止」、Esc、開始条件・保存・設定変更、画面を離れた際に停止する。停止後のWorker結果は適用しない。
6. 100ラウンドの区切りは「再生」で次の手番を開始。記録上限65,536命令・8MB、ブラウザー保存容量の制約を維持する。

移動先、攻撃対象、主/副武器別のダメージ範囲、輸送・生産の候補は自軍の観測だけから求める。未知敵に接触した移動は共通エンジンで途中停止する。命令が適用できなかった場合は別命令や手番終了に自動置換せず、現在の記録を保持して通知する。生産候補は選択した施設・資金・部隊枠を使用する。

## 視界・手番・終局

自軍生存中かつ未決着では、敵手番中も自軍視界に固定する。全体/敵視点選択を無効にし、リプレイ中も同じ制限をかける。敵の未視認部隊・資金・搭載・兵站情報を操作候補や表示へ渡さない。CPUは自軍の手番を計画せず、他軍や敵手番からの人間の命令を拒否する。

自軍脱落時に敗北を表示して停止し、「残りを観戦」で続行できる。以後は全体/各軍視点を選べる。勝利・引き分けで命令とCPU進行を止め、記録保存・再生を可能にする。

## 保存互換

- 参加対局は `format: ministr-four-army-match`、`schemaVersion: 2`、必須 `humanArmy: army1..army4`。生存・未決着中の `view` は担当軍と一致しなければ拒否する。
- 従来の `ministr-four-army-spectator` schema1/2は従来どおりCPU観戦として読込む。担当軍を推測して追加しない。参加対局を旧版で読み込むと未対応形式として安全に拒否される。
- 同じ4軍専用2枠を使用。上書きは明示確認。通常2軍・研究保存に混在させない。JSON再開/書き出し、履歴リプレイ、全体バックアップにも担当軍を保持する。
- マップ固定初期条件・全命令・最終状態を検証する既存コーデックを使用。ファイル由来チェックポイントを信頼しない。担当軍、手番、乱数、CPU版、経路規則、命令列を保持し、常に停止状態で再開する。
- 未確定命令や処理途中のWorkerは保存しない。履歴を変えず、旧保存のCPU・経路規則を維持する。CPU版の明示切替は担当軍も保持する。
