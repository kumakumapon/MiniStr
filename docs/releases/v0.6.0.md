## 主な変更

### CPUの部隊連携

- 前衛・間接砲・対空・補給・輸送・作戦対象を区別し、前衛を動かした後に支援部隊が追従するようにしました。確認済みの敵と公開された作戦目標に基づいて判断します。
- 護衛対象が利用できる護衛から離れすぎないようにし、確認済みの致命的な火力を避けます。任務対象の補給車への自動搭載を止め、降車で脱出が遅れる問題を修正しました。到達後すぐ撤退できる出口への移動を優先します。
- 海上部隊は既存の移動順と射撃位置の評価を維持し、補給に戻る艦のために港を空けます。島の作戦では、輸送できない地上増援を増産し続けず、輸送と艦砲支援へ資金を残します。

### 護衛・撤退作戦

- 単体作戦「補給隊を護衛せよ」「撤退路を開け」を追加しました。既存の通常11マップとキャンペーン10作戦は維持します。
- 護衛は指定部隊を、撤退は指定候補から必要数を脱出地点へ送り、撤退操作で生還させます。目標・対象・脱出地点・進行を出撃前と盤面で確認できます。エディタでも両目標を設定できます。
- 移動後でも未行動なら撤退できます。輸送中の部隊と、部隊を搭載中の輸送車両は撤退できません。必要数の生還が不可能になると対象喪失による敗北になります。
- 撤退した部隊は撃破として数えず、実際のHP・経験を生還記録に残します。生還部隊はキャンペーンの評価・経験継承にも反映します。

### 出撃前編成

- ブリーフィング内で、初期配置の枠・地形適性・領域・予算を守って兵科を選べます。CPU対戦は赤軍、2人対戦とCPU観戦は両軍を編集できます。練習作戦は固定編成です。
- 護衛対象と輸送艦を固定し、占領目標に必要な歩兵系を保持します。予算超過などの理由を表示し、既定編成へ戻せます。
- 未使用予算は開始資金へ一度だけ加算します。キャンペーンの経験は、選択した兵科へ経験の高い生還者から1対1で割り当てます。選択した編成と支援は開始時のスナップショットへ固定します。

## 保存互換性と既知の制限

- セーブ／リプレイとキャンペーン進行はschema v4を維持します。新規対局は`ruleVersion: 6`で、v0.5.1以前の対局は記録されたルールで継続・再現します。保存データの新目標・撤退状態・対象ID・所有者・脱出位置・搭載関係を検証します。
- v0.5.1などの旧アプリはルールv6の対局を読み込めません。旧版へ戻す前に、必要なセーブとバックアップを保存してください。キャンペーンの解放順・最高評価・経験記録の形式は維持します。
- PC幅1280×800とモバイル幅390×844で主要操作を自動検証しています。iPhone／iPadなどの実機でのタッチ操作と聴音は未確認です。BGMは利用者の操作後に再生するブラウザーの制約に従います。
- 依存パッケージと音楽素材は変更していません。今回、新たな依存監査は実行していません。監査履歴は[依存・配信レビュー](../reviews/2026-10-02-dependency-delivery.md#2026-10-16-再評価pr-163)を参照してください。
- GitHub Pagesは`main`に追随し、タグ固定のプレイ画面ではありません。タグ時点のコードはGitHub Releaseのソースアーカイブを参照してください。
- その他の拡張候補は[Issue #213](https://github.com/kumakumapon/MiniStr/issues/213)で追跡します。
