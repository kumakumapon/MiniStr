## 主な変更

### 仮設橋とCPU

- 未移動・未行動の工兵が、視認済みで空いている隣接水域へ仮設橋を建設できます。対岸が地上部隊の通れる地形である1マス幅の水域が対象で、費用1000G、各軍2か所まで。建設後は工兵の移動・行動が終了します。
- 完成した橋は両軍の地上部隊が移動コスト1で利用できます。艦船・航空機も通行し、1マス1部隊を維持します。橋の位置は公開され、周辺の敵部隊は従来の視界規則に従います。
- 建設の確認・中止・Esc・取り消し・保存再開・リプレイに対応します。橋は対局終了まで残り、破壊・撤去や複数マスの架橋には対応しません。
- CPUが迂回との差を評価して接近・架橋し、橋や岸で後続を塞いでいる部隊を移動します。目標保持中の部隊は維持し、公開情報と視認済みの敵に基づいて判断します。

### 生成マップと単体作戦

- マップ生成に「前線補給・工兵」を追加しました。補給所2か所と工兵各軍1部隊を180度回転対称に配置する生成v3です。16／20／24の各サイズ・海域設定とseed指定に対応します。
- 標準生成と保存済みv1／v2の定義を維持し、新設定は独立したシナリオスナップショットへ保存します。内陸河川の自動生成は含みません。
- **橋頭堡を確保せよ**：19×14。対岸の指定補給所を占領し、地上部隊で2ターン保持します。
- **対岸への撤退**：19×14。指定3部隊のうち2部隊を脱出地点から撤退させます。必要数が生還できなくなると敗北します。
- 両作戦の期限は60ターン。迂回路も利用でき、出撃前編成・戦績・追加チャレンジに対応します。単体作戦は計11本になります。

### 観戦・タイトル・マップ表示

- CPU観戦中は「CPUをスキップ」を無効化しました。観戦の進行は速度設定と一時停止・再開で調整できます。通常の対CPU戦ではスキップを引き続き利用できます。
- マップの50%表示を追加し、ユニット・HP・所属・状態・拠点の記号も縮小しました。詳しい情報はユニット／マスのパネルで確認できます。
- タイトルにCPU速度（0.5／1／2／4倍）を追加しました。対局画面と共有し、単体作戦・キャンペーン・観戦へ反映します。
- タイトルの「マップ表示サイズ」で、自動／50／75／100／125／150／200%を選べます。対局中の拡大・縮小とも連動します。
- 同じタブ内では設定を共有し、手動倍率は作戦開始・再開・保存した対局の読込・画面回転後も維持します。「自動」に戻すと画面幅とマップ幅から再計算します。ページ再読込時は倍率が自動、CPU速度が1倍に戻ります。
- 変更後のフォーカスを維持し、利用できない倍率・速度の入力を拒否します。

## 保存互換性と既知の制限

- 新規対局は `ruleVersion: 9` です。旧対局は記録済みの規則で継続します。セーブ／リプレイとキャンペーン進行のschema v4を維持し、橋の状態と建設命令を検証・再生します。
- v0.9.0以前のアプリはルールv9の対局を読み込めません。旧版へ戻す前に必要なデータを全データバックアップへ書き出してください。
- 先攻・後攻の偏りや、作戦・生成seedごとの難度差は残っています。生成比較216条件のうち前線v3の108条件は赤57勝／青51勝でしたが、条件別には大きな差があり、追加seedでは傾向が変わりました。全seed・人間同士の公平性を確認した結果ではありません。
- 新作戦の確認40条件では橋頭堡が赤10勝／青10勝、撤退が赤4勝／青16勝でした。撤退は対象喪失で敗北する非対称の難しい作戦です。人間の攻略難度とCPUの部隊保護は継続評価です。
- PC・スマートフォン幅とChromium／Firefox／WebKitで確認しています。iPhone／iPad実機でのタッチ操作は未確認です。
- 依存パッケージ・音楽素材の更新はありません。基準SHAの2026-10-22のCIで `npm ci` は4件（moderate 3、high 1）を報告しました。独立した最新 `npm audit` と利用者への影響特定は今回行っておらず、[Issue #168](https://github.com/kumakumapon/MiniStr/issues/168)で継続管理します。
- GitHub Pagesは `main` に追随します。タグ時点のコードはGitHub Releaseのソースアーカイブから参照できます。
