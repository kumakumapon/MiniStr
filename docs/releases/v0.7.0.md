## 主な変更

### 偵察履歴

- 視界外になった敵の最終確認位置・兵科・確認ターンを、盤面の破線の「?」と索敵記録に表示します。記録から確認地点へ移動でき、盤面の記号を表示・非表示にできます。
- 記録は過去に見えた情報です。現在そこにいることを示すものではなく、再索敵して空になった地点の記録は消します。攻撃候補とCPUは現在の視認情報を使います。
- 保存再開・取り消し・リプレイの前後シークでは、選択した時点までの履歴から再構築します。各視点で最大256件を保持します。

### 編成プリセット

- 出撃前編成を作戦・陣営別に3件まで名前付きで保存し、適用・上書き・削除できます。
- 適用時にも現在の配置枠・予算・地形・固定部隊・作戦目標を検証します。開始資金と経験は現在のシナリオとキャンペーン進行から計算します。
- プリセットを全データのバックアップ・復元に含めます。不正データや保存失敗は通知し、破損したプリセットは専用の初期化操作で復旧できます。

### 単体作戦3本

- **港湾争奪戦**：中央の港を占領して2回連続保持。占領後は艦艇でも守れます。
- **二つの要衝を守れ**：二つの自軍都市を地上部隊で5回連続保持します。
- **包囲網を突破せよ**：指定された3部隊のうち2部隊を脱出地点へ撤退させます。
- いずれも期限は60ターン。既存の単体作戦2本に加わり、単体作戦は計5本になります。通常11マップとキャンペーン10作戦の定義は維持します。

### 観戦分析

- 全体表示のCPU観戦と全体視点のリプレイで、部隊数・収入・累計損失のグラフと数値表を表示します。最大256ターンの推移と、直近8ターンの攻撃・生産・占領・撤退・損失を確認できます。
- 撤退と合流は損失に含めません。通常のプレイヤー視点では全体分析を表示せず、リプレイの途中位置に未来の情報を残しません。

### 対称マップ生成

- タイトルから16×12／20×16／24×20のサイズ、海域なし／少なめ／多め、seedを指定して戦域を生成できます。同じ条件から同じ定義を作成し、カスタム作戦として保存します。
- 地形・施設の所有・初期兵力を180度回転対称にし、全施設への陸路と港間の航路を検査します。後攻の開始資金補償は+2000Gです。

## 保存互換性と既知の制限

- v0.6.0からセーブ／リプレイとキャンペーン進行のschema v4、新規対局の`ruleVersion: 6`を維持します。偵察・分析は既存の操作履歴から復元し、新しい作戦と生成マップはシナリオスナップショットへ固定します。
- プリセットは独立したschema v1のローカル保存です。v0.6.0のアプリにはプリセットや今回の表示機能はありません。v0.5.1以前の旧アプリはルールv6の対局を読み込めません。旧版へ戻す前には必要なデータをバックアップしてください。
- **対称な配置でも先攻・後攻の勝率が等しいとは限りません。** 16×12・同難易度の小標本9局は赤7勝／青2勝で、海域少なめの3局はすべて赤軍勝利でした。後攻補償を+4000Gとした追加9局でも色別勝利数の改善を確認できず、初版は+2000Gを維持しています。seed・サイズを広げた比較と調整は[Issue #213](https://github.com/kumakumapon/MiniStr/issues/213)で継続します。
- PC幅1280×800とモバイル幅390×844で主要操作を自動検証し、画面を確認しました。iPhone／iPadなどの実機でのタッチ操作は未確認です。音声はブラウザーの自動再生制約に従います。
- 依存パッケージと音楽素材は変更していません。今回、新たな依存監査は実行していません。監査履歴は[依存・配信レビュー](../reviews/2026-10-02-dependency-delivery.md#2026-10-16-再評価pr-163)を参照してください。
- GitHub Pagesは`main`に追随し、タグ固定のプレイ画面ではありません。タグ時点のコードはGitHub Releaseのソースアーカイブを参照してください。
