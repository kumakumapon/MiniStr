# v1.4.5 計画

## 対象

v1.4.4を基準に、390幅・32×32の選択、初回表示、画面復帰の応答を改善し、描画・入力処理を必要な範囲で段階的に整理する。

## 手順・完了条件

1. 計画文書だけでドラフトPRを作成してから製品コードへ着手する。
2. 実ユニット選択のhandler／2frame待ち、初回読込・開始・復帰、layout／long taskをPC／390幅・16／32盤面で測定し、重い箇所を絞る。
3. 描画・入力の責務をUIモジュールへ分離し、不要な生成・DOM更新・再配置を削減する。新規キャッシュの保持量を限定し、古い状態・言語・視点・入力可否を残さない。
4. タッチ初回、スクロール・ズーム・キーボード・フォーカス、霧の情報境界、観戦停止・追従、保存・リプレイ・言語切替を回帰確認する。ゲーム規則・CPU判断・マップ・保存schema・依存・CI権限と既存品質基準は変更しない。
5. 同一条件で変更前後を交互3組比較し、初回と連続選択、計算と描画待ちを分けて全raw・失敗・限界を保存する。実機性能を保証しない。
6. 単体・配布UI・型・lint・整形・coverage・build・ブラウザ・正式CI／CodeQLを確認する。ローカルと正式lockfileの差を明記する。
7. package／lock・README・公開ノートを1.4.5へ同期し、結果をIssue #168とPRへ記録する。Issueの既存履歴を保持する。
8. 検証完了後にPRをレビュー可能へ変更。マージ後main／Pagesを確認し、v1.4.5の正式Releaseを準備する。実機とキャンペーン拡張は低優先度を維持する。
