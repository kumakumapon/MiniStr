# v1.4.2 計画

## 対象

CPU観戦の一時停止操作と、ブラウザ保存の完全同時書き込み保護を実装する。基準はv1.4.1のmain b2203afea877f2bb6188121cb7a11e7cecb60065（tree eea8a8fac8fb5cb948a6a080f96a1301e4c7d411）。

## 手順・完了条件

1. この計画だけでドラフトPRを作成してから実装する。
2. 戦闘演出中も観戦の一時停止とメニューを操作可能にする。停止では演出を安全に終了して盤面へ戻り、明示的な再開までCPU命令を開始しない。確定済みの戦闘結果・履歴を保持し、予約タイマー・遅いCPU応答・二重操作を回帰確認する。日英・PC／390幅・音声復帰・既存の演出スキップと通常対局を維持する。
3. 保存の同期APIと既存snapshot・競合検知を調べ、Web Locks等によるタブ間の排他を追加する。複数キーの保存／復元中にも他タブの書き込みを入れない。排他を取得できない場合・未対応環境・容量不足で成功と誤表示しない。破損原本出力・正常対局救出・旧保存／リプレイを保持し、実際の2タブと失敗経路を検証する。
4. 必要な回帰テストを追加・実行し、型・lint・整形・既存coverage・build・リンク検査、正式lockfile CI・Node22.13・3ブラウザ・CodeQLを確認する。閾値・timeout・retry・公開条件・権限を緩和しない。
5. package／lock・README・公開ノートを1.4.2へ同期。結果と制限をPR／Issueへ記録し、検証完了後にレビュー可能へ変更する。
6. マージ後main CI／CodeQL・Pagesと対象SHAを確認してから正式Releaseを公開する。今回の対象にCPU重み・マップ・ゲーム規則・長期メモリ最適化は含めない。
