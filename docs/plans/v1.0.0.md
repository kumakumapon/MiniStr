# v1.0.0 実装計画

v1.0.0は「保存データとルールの互換性を約束できる版」とする。1.x系では、ここで確定した保存形式とルールを維持し、旧データを安全に読み込めることを保証する。

## 採用範囲

### ルール・保存形式の変更（ルールv12）

- 回数制限付き広域偵察：指定地点の周囲を自軍のその手番だけ視認範囲に追加する。初期案は各軍2回・半径3（調整候補）。視認済み情報だけを使うCPUの制約を守り、未索敵情報を漏らさない。
- 橋の破壊：v0.9.5の仮設橋を破壊できるようにする。破壊手段・費用・制限は試作で確定し、CPUと渡河作戦の評価に反映する。
- 名前付き継続部隊・分岐キャンペーン：キャンペーン間で部隊を引き継ぐ。保存形式の拡張を伴うため、schemaを上げる場合は旧schema 4の読み込みを維持し、不正値は書き込み前に拒否する。
- 軍方針（CPUの性格付け）：CPUの行動傾向を選べるようにする。視認済み情報だけを使う既存制約と難易度との関係を整理する。
- 新規対局はルールv12、旧ルールの対局・リプレイは記録済みの規則で継続する。旧アプリでv12の保存を開けないことをリリースノートに明記する。

### 機能・修正

- #231 生成マップの条件を共有リンク（URLハッシュ）で渡す（第1段階）。生成版・サイズ・海域量・戦域設定・seedを含め、確認画面を挟み、既存保存を上書きしない。
- #233 `main.ts` のタイトル画面を `src/ui/` へ切り出す。動作は変えず、#231の前に行う。
- フィールドBGMのループ継ぎ目を修正する。まずブラウザで継ぎ目を実測し、Web Audioのバッファループを第一案として検討する。戦闘曲・位置復元・音量/ミュート・既存の再生許可方式との整合を確認する。

### 1.0.0の品質整備

- 互換性の約束（保存schema・ルール・リプレイ・バックアップ）を `docs/persistence-schema.md` などに明記する。
- `docs/release-readiness.md` は2026-08-02時点の履歴のため、現状の公開前確認記録を新規に作る。
- `npm ci` の監査サマリー（直近は5件）を最新の `npm audit` で確認し、利用者への影響と対応を判断する。#168・#155の未完了項目は1.0前に対応する分と1.x以降へ送る分に仕分ける。

## 実施順

1. BGMループの実測・修正
2. #233 タイトル画面の分割
3. #231 共有リンク（第1段階）
4. ルールv12：広域偵察 → 橋の破壊 → 軍方針 → 継続部隊・分岐（保存形式の変更は最後）
5. 互換性文書・公開前確認・監査対応
6. 本体/lockfileを1.0.0へ更新し、リリースノートを用意する

各項目は別PRに分け、UI整理とルール変更を混在させない。規模が大きいため、各PRは計画のドラフトPRから順に進め、1項目ずつ差分レビューを通す。

## 確認

- ルール変更ごとに成功・失敗ケースの単体テスト、保存/リプレイ、CPUの情報境界、UI統合を追加する。旧ルールとの対局比較と、攻略用CPUによる全作戦の通し確認を従来どおり記録する。
- 保存形式の変更では、旧データの読み込み・拒否・バックアップ復元を確認する。外部JSONのサイズ・構造・値域検証を維持する。
- lint・形式・型・カバレッジ・ビルド・リンク検査、PC/スマートフォン幅の画面を確認する。

## 対象外

- 実機iPhone/iPadの確認は1.0.0の条件にせず、未確認事項として明記する。
- 依存更新は、監査で必要と判断した場合を除き行わない。

## 公開

- 計画のみでドラフトPRを先に作り、CI/CodeQL成功後にレビュー可能へ変更する。マージ後のmain CI・Pagesを確認し、そのコミットを1.0.0の公開対象とする。
