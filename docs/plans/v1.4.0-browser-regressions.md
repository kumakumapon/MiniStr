# v1.4.0 マージ後ブラウザ回帰の安定化

## 背景

PR #256はmain `08fd4b9d45a60b0f0058fe3c387b8d46e9501fb3` にマージ済み。ソースtreeはPR最終検証と同一の `95688e091c02dff97e6843e55dd106cb8fc365f8`。

main CI run 41281844165の初回はWebKitの大盤面・日本語1280幅が30秒のケース全体上限を超え、453成功・1失敗。変更なしの再実行ではそのケースは成功し、同時射撃1280幅の日英2件が撮影後の `#battle-scene-skip` 待機で停止（452成功・2失敗）。後者では実時間で戦闘画面が自動終了する処理と撮影／操作の競合を疑うが、失敗traceは転送上限・ネットワーク制限により未取得であり、確定原因とは扱わない。

## 方針

1. 計画のみでドラフトPRを作成してから修正する。
2. 戦闘演出テストでPlaywrightの仮想時計を使い、自動終了の時間と画面撮影・手動スキップを分離する。演出表示・スキップ・両軍弾薬／HPの検査を維持し、自動終了も別途検査する。
3. 大盤面の観戦・復帰と、生成マップの保存・再読込を独立ケースにする。全操作・全assertionを維持し、ステップ名で停止箇所を識別できるようにする。
4. timeout、retry、assertion、coverage閾値、CI権限、公開条件は緩和しない。ゲーム規則・UI実装・保存形式・依存は変更しない。
5. 型・lint・整形・build・関連ブラウザを確認し、正式lockfileのCI／CodeQLで全体回帰を確認する。環境制限による未確認は明記する。
6. #213へ初回／再実行／修正検証を区別して記録する。v1.4.0の正式Releaseは修正PRのマージ後main検証・Pages公開成功まで保留する。

## 対象

`tests/e2e/tactical-rules.spec.ts`、`tests/e2e/wide-front.spec.ts`、本計画、確認記録。ゲーム本体への変更が必要と分かった場合は、根拠と回帰検査を追加して範囲を見直す。
