# v1.4.7 計画

基準は正式公開済みv1.4.6 main `0342b69444a5b6910ec9f25e025ac9bf619bc043`、tree `a241a21d7f40ff3ca5e31ec541fbd690f0282a69`。ローカルは同じtreeの `dd13faebe0983d39dd52dba750d8ffb32a2264b1` を凍結する。対応範囲はIssue #264の次の実装セット。

## 順序と完了条件

1. この計画だけでドラフトPRを作成してから製品コードへ着手する。
2. 初回表示・タイトル往復復帰・390幅／32盤面の応答を、同じharness・環境の変更前後で計測する。Chromium／Firefox／WebKitを区別し、ローカルで不足するnative環境は正式CIで補う。初回／連続操作・handler／描画待ち・起動準備を混同しない。測定で特定した重い処理を小さく修正し、フォーカス・スクロール・ズーム・日英・初回タップを維持する。
3. 既存戦術を使う短い単体作戦2本と、目標達成までの段階的な案内を追加する。移動・戦闘・占領完了・生産・補給・輸送／渡河を既存機能で学べる構成を検討。案内は既存の折りたたみUIへ接続し、盤面を覆わない。進捗は自軍の合法な行動と確認可能な状態から導出し、相手の行動や隠れた情報で完了しない。取消・保存再開・旧ルール・日英にも対応する。
4. 新作戦は合法な手順による攻略と、CPUの目標理解を確認する。既存作戦の定義・revisionを維持し、旧セーブ／記録済みリプレイを失効させない。作戦追加がキャンペーン進行・日替わりの既存決定性へ影響しないように確認する。
5. CPUはv1.4.6で差が出た32内陸／沿岸を中心に、先後・方針・難易度・seedを固定して原因を分解する。修理・目標保持・補給の仮説を最小fixtureで確認。実証できた問題だけ修正し、未使用条件・旧ルール対照で採否を判断する。修理HPの総量や相関した往復勝数だけで全般的な改善を主張しない。可視情報限定・合法性・不変state・決定性・実行予算を維持する。
6. 必要な回帰テストを追加し、型・lint・整形・単体／coverage・build・配布UI・3ブラウザー・リンク・CI条件・Node22.13互換・最新監査・CodeQLを確認する。比較のraw・固定source／harness・再現手順・失敗履歴・未確認範囲を残す。既存の時間制限・coverage・色差・反復・retry／skip・権限／公開条件を緩和しない。
7. package／lock・README・公開ノートを1.4.7へ同期し、Issue #264とPRに結果を記録。完了後にPRをReadyへ変更する。マージ後main／Pagesと検証済みartifactを確認し、正式Releaseを準備する。

依存追加・ゲームの戦闘規則・新しい軍方針／指揮官・PWA・キャンペーン拡張は今回の対象外。新作戦と案内、計測で必要と確認した描画／CPU改善に範囲を絞る。
