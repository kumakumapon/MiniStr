# v1.4.4 計画

## 対象

v1.4.3を基準に、CPUの守勢・部隊連携・兵站と問題マップ（wide-front等）の先後バランスを改善する。

## 手順・完了条件

1. 計画だけのコミットでドラフトPRを作成してから製品コードへ着手する。
2. 変更前のCPUとマップを固定し、先後交換・20／32盤面・陸海・目標・軍方針・難易度・未使用seedで比較する。CPU変更とマップ変更の効果を分け、試案と不採用結果も保存する。
3. 守勢の危険判断・支援・補給の合流と継続を調べ、公開情報限定・合法性・決定性・処理予算を維持する。小標本で公平性や全般的勝率改善を断定しない。
4. マップ改善は旧snapshot・生成seed・保存済み対局の再現を維持し、新規定義を識別する。戦闘規則・保存schema・依存・CI権限と品質基準は変更しない。
5. 回帰テスト、型・lint・整形・coverage・build・ブラウザと32盤面の操作応答を確認。正式lockfileはCIで検証し、ローカル環境との差も記録する。
6. package／lock・README・公開ノートを1.4.4へ同期し、全raw・再実行条件・限界を確認文書とIssue #168・#213へ記録する。
7. 検証完了後にPRをレビュー可能にする。マージ後main CI・CodeQL・Pagesを確認してv1.4.4の正式Releaseを準備する。実機・キャンペーン拡張は低優先度を維持する。
