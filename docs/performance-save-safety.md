# 性能改善・保存データ保全

対象: #168・#155。v1.2.0を基準に、ゲーム規則・保存schema・公開条件を維持する。

- 32×32の対局開始・選択・連続CPU観戦の重複計算と描画を調査し、前後計測する。
- CPU思考をWeb Workerで実行し、一時停止・中断時はWorkerを終了する。Workerを生成できない環境では従来の同期計算を使用する。
- 現在の不変ゲーム状態だけに視界・移動・危険域・地形表示のキャッシュを保持する。偵察履歴の視界計算重複を削減する。
- 取り消し履歴は指令位置を保持し、完全な盤面はサイズ別に2〜32件（32×32は8件）だけ保持する。古い取り消しは既存の指令履歴から再現する。
- 保存はタブ内のスナップショットを保持する。各書き込み直前とタブ復帰時にブラウザ保存領域と照合し、変更があれば書き込みを停止する。競合時に古いタブのバックアップと現在の対局を書き出せる。
- 破損セーブも元データを書き出せる。セーブまたはバックアップから検証に成功した対局だけを新規スロットへ追加する。設定や破損対局は救出対象にせず、通常の完全復元は従来どおり全件検証する。
- 単体・保存互換性・PC／狭幅ブラウザ回帰、型・lint・整形・build・リンク検査を行い、結果と制約を記録する。

計画だけのドラフトPR #252作成後に実装。リリース番号は変更しない。

## 制約

- localStorageは複数キーの原子的トランザクションを提供しない。観測した競合を拒否する方式であり、複数プロセスの完全同時書き込みを直列化する保証はない。
- 古いタブのバックアップはそのタブの保存スナップショット。未保存の操作は「現在の対局を書き出す」で別途保存する。
- 救出は対局だけを追加し、戦績・キャンペーン進行・設定を統合しない。現在のカタログで検証できない対局は除外する。スロット上限や保存容量を超える場合は追加を拒否する。
- 取り消しの盤面保持は上限があるが、指令履歴・ゲームイベント等を含むアプリ全体のメモリ上限を保証するものではない。古い取り消しは再現計算に時間がかかる。
- 実機iPhone／iPadは指定どおり低優先度で後回し。
