# 4軍CPUの停滞・方向差の限定修正（v1.5.15）

## 再現と原因

v1.5.14の固定比較 `orders-15141-14`（seed15141、手番3→2→1→4、normal/均衡）を再実行し、3,773命令・401ラウンドの未決着、命令SHA-256 `138ca0a83130a83ae395c4ee96ce27b570cb2d2a3821a388ac18fe2cecb178bd` と最終状態 `971094ad33c77eb4712ac23bd78beb64df0905959a4f86f96ce0442ddb294c48` の一致を確認した。

視界外の自軍工場を敵が占有していると、生産命令は観測上合法でも実エンジンに拒否される。従来は、その生産を部隊の行動より優先し、拒否時の安全なendTurnで未行動部隊まで手番を失った。この条件で681回発生し、終盤は両軍が同じ工場への生産と手番終了を繰り返した。敵の隠れた占有をCPUへ渡したり、失敗後に私的状態を使って別の工場を探したりして解消しない。

もう一つは方向・識別子に依存する同点処理。対称な初期局面を90/180/270度回転し、軍・初期IDを対応させても、3番目の判断で移動先が分かれた。到達候補16件への絞り込みが絶対y/x順、最終同点キーが絶対座標と生の部隊IDだった。第3軍だけへ補正を付けず、全軍が同じ基準で選ぶようにする。

## CPU v2の差分

- 視界外の生産候補だけ評価を1,000下げ、観測上合法な自軍部隊の行動を先に終える。生産候補間の兵科・資金・補給・対空評価は維持する。見えない空き工場からの正当な生産も残し、失敗しても未行動部隊の手番を失わない。
- 公開された自軍司令部の位置から、同じ向きの座標系を作る。到達候補の絞り込みと最終同点キーにはこの座標と観測できる部隊の位置・兵科を使い、生のIDを最終同点基準から外す。方角や第何軍かを有利にする係数は加えない。
- ゲーム規則、戦闘乱数、固定32盤面、初期戦力、価格、軍別上限、視界・敵情報の公開範囲、2軍CPUは変更しない。拒否時の安全なwait/endTurnとWorker取消・世代照合を維持する。

## 保存と旧CPUの継続

| 保存のCPU識別子    | 読込・再生                        | 続きのCPU判断                      |
| ------------------ | --------------------------------- | ---------------------------------- |
| `four-army-cpu-v1` | schema1/2とも全履歴を検証して読込 | 明示的に切り替えるまで旧判断を保持 |
| `four-army-cpu-v2` | 同じ保存上限・全履歴検証で読込    | 改善版を使う                       |
| 未知の識別子       | 原本を保持して拒否                | 適用しない                         |

新規対局はv2。旧保存を読んで書き出すだけでは、CPUを自動変更しない。「軍別CPU設定」の「改善版CPUへ切り替え」で、現在局面・乱数・適用済み命令prefixを保持したまま、今後の判断だけを変更する。停止状態を保ち、元の保存枠は明示的に保存するまで書き換えない。再保存したCPU識別子はその後の判断の版であり、過去の全命令をその版で再決定する指定ではない。履歴再生は保存命令をそのまま実行する。

公開保存のschema2・65,536命令/8MB、専用2枠とバックアップ、検証済みチェックポイントは維持する。旧版アプリは未知のCPU v2を拒否する。エンジンのschema2/four-army-v2とは別の版であり、2軍・研究保存には接続しない。

Worker protocol1へCPU識別子を追加した。新しいPlannerは常に明示し、識別子のない従来protocol1要求はv1として扱う。要求ID・世代・行為軍・ラウンドの一致、旧Workerのterminate、遅延応答の無効化は維持する。

## 比較と検証

候補を固定してから201回を実行した。従来88条件の新版88回、未使用56条件（normal/均衡の全24順×seed15151/15152、混合設定8条件）の新旧112回、旧CPUの既知3,773命令の完全一致再現1回。従来88条件の旧版結果は公開済みJSONを保持し、同じIDの新版と比較する。400/1,000ラウンド・65,536命令の計測予算は維持し、未決着を引き分け・勝利に変換しない。

命令/最終状態のdigest、軍別/開始位置別の勝利、脱落・再開・拒否、生産拒否時の未行動部隊、CPU時間を記録する。normal群の回転軌道では、座標・初期ID・軍を戻した全命令digestも照合する。混合難易度/方針を同設定の勝率に混ぜない。

全201回・12比較jobが完了。新版144条件で、未行動部隊を残す視界外生産とその生産拒否はどちらも0回だった。既知の停滞条件は3,773命令/401ラウンド未決着から15,195命令/262ラウンド・第1軍勝利へ変化した。旧CPUは命令/最終stateのhash一致を再確認した。旧停滞stateから新版へ切り替えた補足再現でも、追加541命令・413ラウンドで第1軍が勝利した。

未決着は計測上限で打ち切った進行中の対局であり、引き分けには含めない。各行は同じIDの前後比較で、混合設定・1,000ラウンド群はnormal/均衡の勝利数へ合算しない。旧決着→新未決着は計9条件あり、JSONにIDを保持する。全条件の改善や勝率の公平性合格とはしない。第3軍の勝利は既存同設定群で6/72→14/72だが、未決着と固定盤面/有限seedの影響が残る。軍別・開始位置別の件数、全条件を分母にした割合、未決着を含めた粗い上下限をJSONに記録した。この上下限は統計的な信頼区間ではない。

同設定の回転30組（各4条件）の全命令digest一致は0/30組。初期のCPU選択の対応と、対局全体の経路/未知敵接触の対応は区別する。候補固定後のseed15151〜15154は今回測定済みであり、次候補の検証では新たな未使用群を用意する。

[全201回のJSON](reviews/v1.5.15/comparison.json)・[停滞/経路差の診断](reviews/v1.5.15/diagnosis.json)・[3ブラウザの値と画面](reviews/v1.5.15/native.md)。比較はsource `86588be3cfe600251fe4014cb7380e13a6599ece`（固定候補+読取専用の計測workflow）で実行。初回run全体は並行した追加試験の準備誤りでfailureとなったが、12比較jobとCPU時間jobは成功している。準備を修正した最終QA run `43521413359` はsuccessで、製品の保存保護やtimeout/retryを緩めていない。

回転した対局の全命令が一致するとは主張しない。seed15141・手番1→4→3→2と、その180度回転を同じ局面・乱数まで追うと、724番目/10ラウンド目はCPUの正規化した移動先が同じでも、エンジン側の経路復元と未知の敵への遭遇で停止位置・燃料が分かれた。絶対y/xで同距離の経路を復元する既存v12規則に由来する。これを変えると旧命令の再現が変わるため、保存互換を設計する別の規則改修として残す。

従来の `four-army:assessment` はCPU v1の再現に固定する。新版の再現は `npm run four-army:cpu-compare -- 0 12 output.json` のshard番号0〜11。末尾へケースIDを渡すと単一条件を選べる。型・lint・整形・coverage、旧CPUの判断、隠れた情報への不変性、旧保存の保持/切替、Worker取消、PC/390px・日英を確認する。既存CI/Pagesの条件・権限・timeout/retryを変えない。

固定マップ・有限seedの比較で、すべての対局の決着や一般的な公平性を保証しない。物理端末のタッチ/支援技術と2/4時間の継続測定は別の残件として管理する。
