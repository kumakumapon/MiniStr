# 広域偵察・拠点支配戦・単体作戦の戦績（Issue #213）

## 採用範囲と進め方

利用者は2026-10-19に、v0.7.0に続く次の3機能と生成マップのバランス評価・改善を採用した。まず本設計だけをコミットしてドラフトPRを作成し、その後に製品コードへ着手する。完了したらCIと画面を確認してレビュー可能にする。マージ・バージョン番号・Release公開は別の作業で確定する。

基準は `ffc7f5e71fda0ddfcfc6fb54c677ff009eca897d`（v0.7.0）。不要な依存、CI権限、公開条件、カバレッジ閾値の変更は行わない。

## 広域偵察

- 新しいルール版で、各軍に1作戦2回、半径3の偵察を用意する。指定地点周辺をその自軍手番中だけ視認できる。手番終了時に一時視界を消し、残回数は保持する。
- 発動は合法性を検査する独立したコマンド。残回数と発動地点を状態・履歴に記録し、保存再開、取り消し、分岐、リプレイの前後シークを再現する。
- 現在の視認と最終確認履歴をつなぎ、見えなくなった敵を現在位置として表示しない。敵の残弾・燃料を開示しない。
- CPUも同じ制約で使う。地点選択に使うのは地形、味方、既知の敵、公開された目標。未索敵の敵位置や兵站を評価根拠にしない。
- UIは盤面付近で発動モードへ入り、マス選択で実行する。中止とEsc、回数・範囲・有効期限、CPU操作中や終了後の無効化を示す。

## 拠点支配戦

- 指定された都市などの所有で、両軍の手番終了後に同時加点する。常駐部隊は不要。撃破・新規占領の従来スコアとは別に集計する。
- 同時到達は得点を比較し、同点は継続する。従来の即時勝利条件とスコア戦を維持する。対象拠点、所有、得点は両軍へ公開する作戦情報とし、隠れた敵部隊を表示しない。
- 初版では両軍に共通の1組の支配拠点・目標点を定義し、異なる支配条件の混在や従来スコアとの混在は入力時に拒否する。
- 新しい目標を読み込み、編集、保存、リプレイ、作戦目標と勝因表示へ通す。CPUが確保・奪還と防衛を評価する。
- 陸上と沿岸の単体作戦を各1本追加する。既存の通常11マップ、キャンペーン10作戦、単体作戦5本の定義を維持する。

## 単体作戦の戦績・チャレンジ

- 組み込み単体作戦を人間が赤軍でCPUと戦った結果を対象にする。キャンペーン、観戦、2人対戦、リプレイ、カスタム・生成作戦は通常の戦績へ加算しない。
- 作戦の版・ルール・難易度・初期編成と資金の条件ごとにクリア、最短ターン、最小損失、追加課題の達成を保存する。自由編成は条件を表示して区別する。
- 最良値と達成済み集合の更新に限定し、勝利回数の累積は行わない。同じ結果の再表示・再読込・取り消しと再勝利は同じ値を再適用しても増えない。
- 課題は規定ターン、味方損失、生還などを作戦ごとに設定する。勝利と追加達成を分けて表示し、能力・資金の強化報酬は付けない。
- 独立した版付きローカル保存に件数・サイズ・構造の上限を設ける。全データのバックアップ／復元にも含める。破損、容量不足、記録上限を通知し、既存データを保持する。
- 作戦選択、折り畳みの戦績一覧、結果画面から確認できるようにする。

## 生成マップの比較と改善

- 生成seedと戦闘乱数seedを区別し、サイズ・海域・難易度・配置方向とともに再現可能な比較記録を残す。
- 既存の比較処理を拡張する。同難易度を軸に難易度と配置を交換し、勝率、未決着、ターン数、初動の施設到達と処理時間を条件別に比較する。
- v0.7.0の9局・赤7勝青2勝を小標本の既存記録として保持する。調整用のseedと評価用のseedを分け、補償金だけで結論を出さない。
- 比較で確認した改善を採用し、改善しなかった条件や未確認の範囲も記録する。必要なら生成方式に新しい版を付け、保存済みの定義を維持する。
- 長い比較は明示した条件と時間・コマンドの上限で実行する。毎回のCIには短い合法性・再現性確認を用意する。

## UI方針

既存の緑・金・暗色、DOM盤面と折り畳みパネルを使う。主要操作と目標を盤面付近へ置き、戦績の長い説明は閉じたパネルへ収める。PCと390px幅、タッチとキーボード、フォーカス、中止と読み上げ、横溢れを確認する。

## 互換性と完了条件

- 新規対局だけに新ルール版を割り当て、旧ルール・旧セーブ・旧リプレイの視認と得点を維持する。セーブ／リプレイのコンテナschema v4とキャンペーン進行を維持する。
- 新しい状態・コマンド・シナリオ条件・ローカル保存の上限と不正入力を検証する。
- 広域偵察とCPUの観測境界、手番での期限、両視点、保存再開、取り消し、前後シークを確認する。
- 拠点の加点、奪還、同時到達、同点継続、CPUの実際の目標達成を確認する。
- 戦績の条件区分、最良値、課題、冪等な更新、バックアップ、失敗時の既存データ維持を確認する。
- 旧回帰を含むunit・coverage・型・lint・format・build・UI統合・ブラウザとPC／モバイル画面を確認する。既存の閾値と検査を維持する。
- 最終コミットのCI、比較結果、画面、未確認事項をPRとIssue #213に記録する。

## 実装と確認記録

- 新規対局はルールv7。各軍2回の広域偵察、手番での失効、CPUの公開目標からの地点選択、保存・取り消し・リプレイを実装した。旧ルールは偵察を使用しない。
- 陸上・沿岸の支配戦を各1本追加。支配条件の読み込み、編集、共有得点、表示、CPUの占領判断、勝因、保存を実装した。
- 戦績は独立schema1で128条件・384,000バイトまで。初期編成と開始資金を含む全条件を比較し、最良値と達成済み課題を更新する。設定の詳細表示、個別削除、不正記録の明示的リセット、バックアップ検証を追加した。
- 既存5本と追加2本の全単体作戦を、赤CPU難しい・青CPU易しいで合法な命令だけにより勝利まで確認した。勝因は護衛・撤退・拠点保持・支配の各目標。護衛5、撤退5、港湾7、防衛5、突破3、陸上支配11、沿岸支配11の完了ターンを記録した。
- 偵察で敵が見えた後の撤退停滞を修正。v7は脱出地点への前進と味方の通路塞ぎ解消を優先する。旧v6の撤退作戦は54ターン、新v7は5ターンの勝利を回帰テストで固定した。
- 偵察・支配欄を部隊情報の上へ配置し、部隊情報は盤面に隣接させる。既存のブラウザ回帰が検出した72pxの間隔を修正し、12px以内という既存検査を維持した。新しいUI統合・支配戦のブラウザ確認にも隣接の検査を追加した。
- ローカルで単体794件・UI統合18件と型・lint・format・build・リンク検査に成功した。カバレッジ閾値は変更せず通過。Vitest5のCIでもカバレッジ・ビルド・UI統合が通過した。ブラウザ・画面と最終コミットCIの結果はPRに記録する。ローカル環境はVitest 3.2.7のため、lockfileのVitest5によるクリーンなCIも確認する。
- 生成マップの調整・不採用案・残る偏りは[比較評価](reviews/2026-10-19-generated-balance.md)に記録する。生成方式v2は開始戦闘乱数を生成条件ごとに分け、旧地形と補償額を維持する。
