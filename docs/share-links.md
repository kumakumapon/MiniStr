# 生成マップの共有リンク（Issue #231 第1段階）

対称マップ生成の条件（生成バージョン・サイズ・海域量・戦域設定・seed）を、URLのハッシュに載せて渡せます。リンクを開いた人は、確認画面で条件を確かめてから同じ戦域と戦闘乱数で作戦準備に進めます。サーバー、アカウント、外部通信はありません。

保存形式（セーブ schema 4、リプレイ、カスタム作戦、`localStorage` のキー）、ゲーム規則、`src/game/mapGenerator.ts` の生成ロジックは変更していません。共有リンクは生成条件を運ぶだけで、受け取った側は既存の「対称マップを生成」と同じ経路でカスタム作戦として保存します。

## 使い方

- 送る側: タイトルの「対称マップを生成」でサイズ・海域量・戦域設定・seedを選び、「共有リンクをコピー」を押します。クリップボードが使えない環境では、リンクが読み取り専用欄に表示されるので選択してコピーします。
- 受け取る側: リンクを開くと確認画面（`role="dialog"`）が出ます。生成バージョン・サイズ（幅×高さ）・海域量・戦域設定・seed・作戦名を確認し、「生成して作戦準備へ」で開始、「キャンセル」（Escでも可）で閉じます。初期フォーカスは安全側の「キャンセル」です。

## 形式

```
#ministr-gen1/{gen}/{size}/{sea}/{preset}/{seed}
```

| 部分 | 意味 | 許可される値 |
| --- | --- | --- |
| `ministr-gen1` | リンク形式の版（`gen1`） | 固定 |
| `{gen}` | 生成ロジックの版 | `2`（標準）、`3`（前線補給・工兵） |
| `{size}` | 盤面サイズ | `16` `20` `24`（盤面は `size × (size - 4)`） |
| `{sea}` | 海域量 | `none` `coast` `ocean` |
| `{preset}` | 戦域設定 | `standard` `frontline`（`{gen}` と組で `2⇔standard`、`3⇔frontline` のみ） |
| `{seed}` | 生成seed | 英数字・ハイフン・アンダースコアの1〜24文字（`mapGenerator.ts` と同じ規則） |

例: `https://<host>/<path>/#ministr-gen1/2/20/coast/standard/MiniStr-1`

リンクは `location.origin + location.pathname + ハッシュ` です。検索文字列（`?...`）は含めません。`http(s)` 以外のオリジン（`file://` など）ではコピーせず、理由を表示します。

最長のリンクでもハッシュ部分は58文字で、メッセンジャーや掲示板に貼れる長さです。

## 検証規則（外部入力として扱う）

`src/game/shareLink.ts` の `parseGeneratedShare` は例外を投げず、次を満たすリンクだけを受け付けます。

- 先頭の `#` を除いて128文字以内（最初に確認）。
- 6つのセグメントがちょうど `/` で区切られ、空のセグメントや末尾の `/` がない。
- 各値が許可リストと完全一致（大文字小文字は区別、`020` のような0埋めは不可）。
- パーセントエンコード、制御文字、Unicode、`decodeURIComponent` による解釈は行わず、seedの許可文字以外は拒否。
- 生成バージョンは `2` と `3` のみ。生成v1は共有リンクでは扱いません。
- 日替わりチャレンジの形式のseed（`D` と数字8桁）は共有リンクにできません。コピー時とリンクを開いた時の両方で拒否します（日替わりの戦域は日付から導出する別の仕組みで、カスタム作戦として保存する対象ではないため）。

拒否理由は固定文言で、入力文字列を埋め込みません（巨大・不正な入力が画面やログに出ません）。拒否したリンクはアドレスバーから消去し、タイトル画面に通知します。`localStorage` には一切書き込みません。`#foo` のような無関係なハッシュは無視し、通知も出しません。`#ministr-gen` で始まるが対応しない版（将来の `gen2` など）は「対応していません」と通知します。

## 版の凍結と将来の方針

- `gen1` のリンクが指す戦域は永久に同じです。`{gen}=2` は生成v2（標準）、`3` は生成v3（前線補給・工兵）で、地形・施設・兵力・戦闘乱数のseedまで `generateSymmetricMap` と一致します。往復テスト（全サイズ×海域×戦域設定）と、既知リンクの地形指紋テストで守っています。
- 将来生成ロジックを変える場合は、新しいリンク形式の版（`gen2` など）と新しい許可表を追加します。`gen1` の表を書き換えたり、旧い値に別の意味を与えたりしません。古いアプリは新しい版を「対応していません」と拒否します。

## 確認画面と既存データ

- 確認画面を開く前に、生成はメモリ上だけで行います。確認前に `localStorage` へ書き込むことはありません。生成に失敗する条件（前線補給所を置けないseedなど）は、確認画面を出さず通知します。
- 確定すると、タイトルの「生成して作戦準備へ」と同じ処理（進行中の対局の置換確認 → カスタム作戦として追加保存 → 作戦準備）を行います。既存のカスタム作戦、セーブ、日替わり記録は上書き・削除しません。追加されるのは1件だけで、同じリンクを何度確定しても同じIDなので重複しません。
- 作戦名はタイトルの生成と同じ決定的な名前で、名前入力欄はありません。
- カスタム作戦が上限（32件）または容量不足で保存できない場合は、対局を開始せず、確認画面に理由（上限なら既存のカスタム作戦を削除する必要がある旨）を表示します。リンクは残るので、削除してから再試行できます。進行中の対局の置換を断った場合も確認画面とリンクは残ります。

## 他の画面が出ているとき（保留）

エディタ、キャンペーン、ブリーフィング、対局中、ホットシートの交代画面、結果画面、生産メニュー、戦闘演出、リプレイ、CPU処理中は、確認画面を重ねません（常にダイアログは1つです）。この間に届いた有効なリンクは**保留**し、画面は変えず、ハッシュも消しません。タイトルが表示できる状態になった次の描画で確認画面を出します。保留中であることは利用者に見えるところでは通知しません（確認画面が出るまで操作を妨げないため）。保留中や確認画面の表示中に届いた不正リンクの通知は、タイトルが次に表示された時に出ます（確認画面の「キャンセル」で消えます）。保留中に別の有効なリンクが届いたら新しい方に置き換え、不正なリンクが届いたら保留中の有効なリンクを残して通知だけを行います。

## プライバシー

URLのハッシュはブラウザーからサーバーへ送信されません。ただし、リンクを貼った先のサービスやブラウザーの履歴には残ります。seedには個人情報や秘密を入れないでください。リンクに含まれるのは生成条件だけで、作戦名などの自由入力は含みません。

## 対象範囲

- 第1段階（本書）: 生成条件だけを共有します。
- 第2段階（別Issue/PR）: 小さなカスタム作戦のJSONを圧縮してハッシュに載せる案があります。URLの長さに上限があるため、上限を超えるものは共有不可として従来のJSONファイル共有を案内する方針です。本書の実装には含みません。カスタム作戦JSON、セーブ、リプレイは共有リンクの対象外です。
