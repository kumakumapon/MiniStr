# 1.x の互換性方針

保存schema、ゲームのルール番号、キャンペーンのschema、バックアップのschemaは別々に管理します。

- 公開済み1.xで作成した正常なデータを、新しい1.xで読み込めるようにします。既存の旧schema移行も維持します。外部入力のサイズ・構造・値域の検査は引き続き適用します。
- 対局のルール番号は開始時に固定します。新機能を加えても、旧ルールのコマンド・兵科・戦闘結果を変えません。旧ルールの保存・再開・リプレイを回帰確認します。
- schemaは構造の互換性、ルール番号はゲーム規則の再現を表します。新しいルールだけを追加する場合、保存schemaを上げる必要はありません。
- 保存構造を拡張する場合は、旧schemaからの明示的な移行を用意し、不正な値を推測で修復しません。キャンペーン進行など独立した保存形式は、それぞれのschemaで移行します。
- 旧アプリによる新形式・新ルールの読み込みは保証しません。未知のschema・ルールを安全に拒否し、公開ノートに必要なアプリの版を記載します。
- バックアップは各項目を検証してから復元し、検証失敗で既存データを書き換えません。保存キーを増やす場合はバックアップの検証・復元・メモリへの反映も追加します。

公開前に対象SHA、移行・旧ルールの比較結果、既知の制限を記録します。公開済みリリースノートは当時の履歴として扱います。GitHub PagesのプレイURLはmainの更新に追随し、タグに固定された体験ではありません。

v1.1.0の追加機能・監査・公開判断は作業中です。この方針の追加だけで、#244・#245の実装や検証が完了したことにはなりません。
