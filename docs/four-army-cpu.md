# 4軍CPU・Worker取消（v1.5.11）

v1.5.10の[実対局基盤](four-army-engine.md)へ、複数敵CPU・軍別設定・実Worker・取消可能な進行管理を接続した。専用32盤面と観戦画面は次段階であり、本版に4軍対局を開始するアプリのメニューは追加しない。

## 判断と情報の境界

- `chooseFourArmyCpuCommand(observation, options)`は軍別観測だけを受け、行為軍付きの基本命令を1件返す。3つの敵軍のIDは観測と命令で区別し、移動/射撃・占領・防衛・修理待ち/補給接近・搭載/上陸・生産を選ぶ。未来の手番を2軍のendTurnで模擬しない。
- 地形・施設所有・元司令部位置は公開情報。敵の隠れた部隊・cargo・兵站・資金・乱数状態は渡さない。視界外の占領進捗も20へ伏せ、捕捉していない歩兵の位置を推測する入力にしない。ほかの敵軍の視界を自軍へ共有しない。
- `observeFourArmy`は公開の元司令部位置を追加した観測DTOを返す。Worker入口ではキー・値域・盤面32以下/128部隊以下・輸送参照・実際の自軍視界と可視敵・敵情報の伏せ方を再検証する。完全なFourArmyStateを送る経路はない。
- 幾何・射撃予測等は観測から作る一時的な自軍/敵の計算盤面で行い、敵軍IDや保存状態を統合しない。予測用乱数は固定値で、実対局の乱数を参照しない。等点は命令のID/座標順で決め、同じ観測と設定なら同じ命令になる。
- easy/normal/hardは生産規模と移動後射撃の計画範囲を分ける。balanced/offensive/defensiveは危険・目標・本拠防衛の重みを分ける。軍別設定は能力値/所持金への加算を行わない。難易度の勝率順・4軍の公平性を実証済みとは扱わない。
- v12相当の基本命令を対象にする。橋/偵察/戦術ON等の未接続命令は選ばない。地形の到達距離、施設別生産、有限物資は既存の規則を使う。行動候補を各部隊の近い16移動先へ絞るが、公開部隊上限・応答性能の確定値ではない。

## Workerと進行管理

- `FourArmyCpuPlanner`はprotocol1・要求ID・世代・行為軍/ラウンド/枠を付けた要求を送る。Workerは観測と当該軍の難易度/方針だけを受け、判断命令を返す。DOM・音・localStorageをWorkerから操作しない。
- 取消はWorkerをterminateし、ハンドラー・保留状態を解放して古いPromiseをundefinedで確定する。要求の差替え、停止、終了、対局/保存状態の切替、設定変更は古い世代の応答を適用しない。再利用したWorker上の古い要求IDの応答も現要求を確定しない。
- Worker作成不可時は同じ計算のfallbackを使う。計算前にmicrotaskへ譲り、取消前後で適用を抑止する。fallbackの同期計算そのものを実行中に中断できるとは扱わない。実Worker経路はterminateで計算を止める。
- 不正な返信・Worker例外・postMessage失敗はWorkerを解放してエラーにし、進行側を一時停止する。正しい命令の返信でも、適用直前に実盤面の合法性を再確認する。
- `FourArmyCpuSession`は状態を所有し、`resume()`後の`step()`で最大1件だけ適用する。状態/履歴のgetterはコピーを返す。pause/configure/replaceState/stopが応答到着後・適用前に入っても世代照合で抑止する。replaceStateは停止状態で新しいcheckpointへ切り替える。stop後の再開は拒否する。
- 観測から見えない占有で生産/移動/上陸が実盤面では不正になる場合、隠れた配置を使って代案を探索しない。その部隊のwait、部隊のない生産ならendTurnを実エンジンで検証して適用する。これも履歴に記録し、失敗命令そのものは記録しない。
- 100ラウンドのエンジン停止と終局は進行を停止し、Workerを解放する。100ラウンド後は明示resume時にだけcoreのresumeを1回適用し、履歴へ残す。勝敗や引き分けへ変換しない。
- ブラウザーからの接続口は`createFourArmyCpuSession`。画面の速度・視点・操作イベントの接続は次段階。セッションに自走するタイマーはなく、呼出元がstepの間隔を管理する。

## 保存と検証

coreのengineVersion1と4軍JSONチェックポイントのformat/schema1/rulesetは維持する。`session.commands`は作成/replaceState以降の適用済み命令差分で、保存元prefixは呼出元が保持して連結する。CPU設定・アルゴリズム版・観戦状態の永続化、名前付きスロット、長い命令列、公開リプレイとバックアップは未接続。通常2軍の保存/リプレイschema4・研究schema1を変更しない。

全24順序×3難易度の制御小盤面、3敵軍への射撃、隠れた情報を変えても同じ判断、資金/施設/補給/輸送、観測/通信の不正入力、遅延・重複返信、要求差替え、pause/stop/replace/configure、返信後の適用競合、失敗・fallback、100ラウンド停止とJSON履歴再現を検証する。Chromium/Firefox/WebKitでも実Workerの取消・全軍進行・終局を確認する。これを専用32盤面のCPU勝率・性能/公平性や実機検証と混同しない。

## 次の4陣営残件

1. 専用32×32マップ1本の司令部/開始域/初期部隊・資金・施設を作り、試作16/軍・計64を比較して公開上限を確定する。
2. 観戦画面へ軍の識別・情報・視点・難易度/方針・速度・停止/再開を接続する。
3. 公開用の名前付き保存・JSON操作・長い命令列・軍別CPU設定・決定的リプレイ・バックアップを接続する。
4. 手番順/配置/seed/方針/難易度の公平性、同じ総部隊数での2軍/4軍のCPU時間・入力応答・メモリ、従来2軍の退行を比較する。

最初のプレイ可能な4軍CPU観戦はこれらを揃えて提供する。旧4はCPU/取消接続までの部分完了で、機能群全体の完了には移さない。
