# 4軍CPU観戦（v1.5.14）

長期保存・比較結果・現在の上限は[長期記録仕様](four-army-endurance.md)を参照してください。以下の操作を維持し、v1.5.13の保存制限を更新しています。

タイトルの「4軍CPU観戦」から、専用32×32「四方の前線」を開始できます。全軍CPU・全軍敵対で、人間による部隊命令や同盟は初版の対象外です。

## 開始条件と操作

seedは0〜4294967295。4軍を1回ずつ指定する手番順24通りと、軍別の難易度・方針を指定します。各軍8部隊・基本資金10,000・搭載込み16部隊上限はv1.5.12の固定条件です。最初の手番には収入を加算します。

開始・再開時は停止状態です。再生、停止、1手送り、0.5/1/2/4倍速、全体/軍別視点、拡大・縮小・全体表示、部隊への移動を提供します。盤面はスクロールで移動し、クリック/タップまたは矢印キーで選択情報を確認できます。盤面にフォーカスしてSpaceで再生/停止、Escで停止します。

設定変更、開始条件への移動、タイトルへ戻る操作、言語変更、背景化、pagehide、対局の置換は進行とWorkerを取り消します。100ラウンドごとに停止し、明示的な再開を履歴へ記録します。終了後も盤面・勝敗・記録を確認できます。2軍の成績・キャンペーン結果へ反映しません。

## 視点と表示

軍の色に加えて部隊へ軍番号を表示します。選択欄と表示中部隊の一覧をDOMで提供し、操作ボタンは44px以上。軍別情報・CPU設定・保存操作は折りたたみ、PCでは盤面の横、狭い画面では下に配置します。日本語/英語を切り替えられます。

軍別視点はその軍の観測だけを表示し、他軍の資金・兵站と未索敵の部隊を表示しません。観戦者が全体表示を選んでも、CPUへ渡すのは行為軍の観測です。

## 公開用保存・リプレイ

専用キー `ministr.fourArmy.save.1` / `.2` に名前付きで保存・再開できます。通常対局・研究保存と分離します。JSON書き出し、JSONからの再開/リプレイ、全データバックアップへの同梱・復元も提供します。全データの復元操作は既存のバックアップ画面を使います。

公開形式は `ministr-four-army-spectator` schema2（旧schema1も読込）、CPU識別子 `four-army-cpu-v1`、内部アーカイブはengine2/schema2です。現在の軍別CPU設定・視点・速度・名前・日時と、固定マップ・全命令・最終状態を記録します。CPU設定は保存時点の値であり、過去の設定変更履歴ではありません。

再開・書き出しは専用Workerで初期状態から履歴を再実行し、最終状態、固定マップ、各値・形式・バージョンを照合します。Workerが生成できない環境では同じ検証へフォールバックします。中断後のファイル応答を適用しません。不正ファイルは現在の対局や既存の保存を置換しません。容量超過・書込不可・別タブとの競合ではJSON書き出しを案内します。

ファイルは8MB、命令は65,536件までです。上限では新しいCPU命令を停止し、保存・書き出しを残します。履歴を黙って切り捨てず、勝敗を代用しません。リプレイは先頭・前・1手送り・末尾・位置指定に対応し、現在の対局とは独立して移動できます。8命令ごとに処理を譲り、2,048命令ごとの検証済み状態と、直近8個までの64命令ごとのキャッシュを使います。研究分岐は対象外です。

従来2軍・研究・engine1/schema1の読取規則は維持します。公開用保存へ任意の旧エンジンチェックポイントを直接取り込みません。旧版の全データ復元は未知の4軍キーを拒否するため、4軍保存を含むバックアップの復元にはv1.5.13以降を使います。

## 次の4陣営対応残件

1. 未決着・軍別勝利差の原因特定と限定CPU改善。全24手番順×3seedでは50勝利/22未決着で、第3軍の勝利が少ない。測定予算を勝敗へ変えず、最初の判断差を比較する。
2. 実機での長時間・タッチ・アクセシビリティの確認。自動ブラウザの最大記録・10分試験と、物理端末の2/4時間測定を区別する。

長期記録の初版拡張と比較基盤はv1.5.14で提供。3軍・人間参加・同盟・通信対戦・4軍研究分岐は別の採否検討です。
